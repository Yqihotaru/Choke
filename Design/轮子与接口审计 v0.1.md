## 0. 一句话结论

现在大约 **44,500 行**代码 / CSS / 脚本（不含 md、JSON、node_modules）：

```text
~10.2k  src/card/faces        6 个卡面版本 + 注册表
~14.0k  src/desk              桌面、书本、抽屉、拖拽、开包、面板
~3.8k   src/card core         卡牌规则、数据、编辑器/实验室
~3.5k   public/holo-lab       全息效果参考页
~2.8k   apps/api              Fastify + PGlite
~2.7k   src/components        旧战斗组件 + 少量活组件
~2.0k   src/battle            当前 master 的旧回合制战斗
~1.9k   src/tutorial          教程状态机 / 对话框 / 台本
~1.6k   src/pool              卡池构建 + 实验室
~1.2k   src/desk/opening      开包动画
~0.8k   scripts               同步 / 构建脚本
```

真正跑起来的循环只有：

```text
登录 → 开包 → 卡册 → 卡组 → 一场战斗 → 市场
```

没有关卡、战斗奖励结算、日常、赛季、PvP、成就。  
所以“轮子不少、实际东西不多”是准确的：**工具和视觉探索跑在内容前面**。

## 2. 后端地图

### 2.1 端点总表（35 个，含 `/health`）

| 模块 | 端点 | 作用 |
|---|---|---|
| 健康 | `GET /health` | 探活，不查 DB |
| 认证 | `GET /auth/osu`、`GET /auth/osu/callback`、`GET /auth/guest`、`GET /auth/me`、`POST /auth/onboard`、`POST /auth/tutorial-pack`、`POST /auth/logout` | osu OAuth、游客、session、新手包、补包 |
| 卡牌 | `GET /cards`、`/cards/stats`、`/cards/countries`、`/cards/:id`、`/users/:id/codex`、`/codex/stats`、`/users/:id/cards` | 公共卡池、图鉴、用户卡册 |
| 卡包 | `GET /packs`、`GET /users/:id/packs`、`POST .../packs/:pool/take`、`.../return`、`.../mystery/open`、`POST /packs/:pool/open` | 库存、桌面 token、开包、神秘包 |
| 卡组 | `GET/PUT /users/:id/deck` | 7 槽主卡组 |
| 市场 | `GET /market/listings`、`GET /users/:id/market/listings`、`POST .../list`、`DELETE .../listings/:id`、`POST .../buy/:id` | 浏览、上架、下架、购买 |
| 养成 | `GET .../fuel`、`POST .../level`、`.../constellation`、`.../melt`、`.../enhance` | 升级、命座、熔卡、镀闪 |
| 进度 | `GET/PUT /users/:id/progress` | 玩家等级/经验/教程步骤 |

### 2.2 DB（10 张表）

`cards`、`users`、`user_cards`、`decks`、`deck_slots`、`user_packs`、`pack_tokens`、`pack_openings`、`pity`、`market_listings`。

事实：

- `schema.ts` 是查询/类型来源，`db/client.ts` 内联 DDL 是运行时 schema 来源；**双维护**。
- 没有 migrations 目录、没有 drizzle-kit、没有版本号；启动时跑幂等 DDL。
- 没有 `FOREIGN KEY` / `references()`；关系全靠应用层。
- `users` 同时存玩家等级/经验/教程步骤/补包标记。
- `market_listings` 用部分唯一索引保证同一 `user_card` 只有一个 active 挂单。

### 2.3 Auth

- osu OAuth：`identify` scope；state 在进程内 `Set`，最多 500；回调 `osu-<id>`。
- 游客：`guest-<12hex>`，`onboarded=true`，30 普通包，无神秘包、无本体卡。
- session：`choke_session = userId.HMAC-SHA256(SESSION_SECRET, userId)`，30 天，httpOnly/Lax；没有服务端 session 表，logout 只清 cookie。
- `SESSION_SECRET`：显式 → `OSU_CLIENT_SECRET` → 进程随机。
- 市场门槛：`tutorialDone === true` 且 `playerLevel >= MARKET_UNLOCK_LEVEL`；等级由客户端 PUT 上传，服务端只做单调合并。

### 2.4 Gacha / Packs

- 权威权重/闪率/保底在 `apps/api/src/gacha/pools.ts`；实际选卡在 `open.ts`。
- 6 个加权池：`normal/idle/golden/radiant/sky/prism`；`mystery` 不走加权，只能 `/packs/mystery/open`。
- 保底：`PITY_THRESHOLD = 60`、最低 `L`，按 `(user, pool)` 存 `pity`。
- 前端 `src/desk/rarity.ts` 是展示副本；`rollPack()` 无调用。
- 前端未调用 `GET /packs`；它直接读本地 `POOL_META.weights`。

### 2.5 Market / Progression

- 市场上架/购买事务内转账、转卡、清 deck slot；下架是硬删除。
- 升级/命座/熔卡/镀闪都由 API 调根 `src/card/progression.ts` / `economy.ts` 的纯函数。
- `LEVEL_CAP`、`CONSTELLATION_CAP`、`MELT_EXP`、`ESSENCE_OF`、`FOIL_COST`、`MARKET_MAX_PRICE` 是前后端共享常量，API 直接 import 根 `src`。

### 2.6 跨层依赖

`apps/api` 有 **11 条** import 指向根 `src`：

```text
auth.ts        → src/pool/hero
market.ts      → src/card/economy, src/tutorial/constants
progress.ts    → src/tutorial/types
progression.ts → src/card/progression, src/card/economy, src/card/types
hero.ts        → src/card/data, src/card/types, src/pool/hero, src/pool/score
```

依赖方向是 **API → 根 src**，而根 `src` 同时是 Vite 前端根。  
`apps/api/tsconfig.json` 用 `@/* → ../../src/*` 才能解析。

## 4. 接口契约

- 成功：`{ ok: true, data: ... }`；错误：`{ ok: false, error: { code, message } }`。
- `src/desk/api.ts` 的 `request<T>` 统一 `credentials: "include"`、抛 `error.message`、返回 `data.data`。
- 但不少组件绕过 `api.ts` 直接 `fetch`：`DeskPage`、`BackpackPanel`、`CodexPanel`、`InviteLetter`、`GachaPanel`。
- `/api` 前缀由 Vite 代理 rewrite；`/auth` 不 rewrite。
- 开包、单卡详情、Codex、auth 写操作多为组件内局部类型或裸 fetch，没有统一 client。
- `GET /packs` 后端有，前端未调用；`GET /cards/:id` 不过滤 `hero-%`。

## 6. 减法候选（只标记，不执行）

### 6.1 低风险

1. **实验室懒加载**：`App.tsx` 对 `CardLab`、`CardEditor`、`PoolLab` 用 `React.lazy` + `Suspense`。
