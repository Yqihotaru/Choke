## 1. 设计原则（v0.3 修正版）

### 1.1 20 万卡池是背景板

- 20 万张不是“要被抽空的进度条”，是社区身份库。
- 玩家留存的四个钩子：**主线战役 / 赛季策略 / 周本阀门 / 刷 MOD 与市场淘卡**。
- 不把“每天手点 60 个挂机包”当留存手段：挂机包必须支持一键开启 + 自动熔炼低阶卡。

### 1.2 低通胀

- 金币必须值钱：开服前 3 个月目标是**紧平衡 + 5–10% 净沉淀**。
- 任何“卡片 → 金币”的通道都要有日限和低于市场价的定价。
- 系统金币只从**任务 + 周本**进入；副本不再产金币。

### 1.3 三条铁律（不变）

1. 改变“下一季配速”的东西必须绑定：体力、阀门、保底产物、挂机卡、签名材料。
2. 商品才允许交易：概率抽出的常驻卡（含 L / Radiant / Prismatic）、金币、MOD、镜像卡。
3. 保底产出绝不进入市场；可交易资产只能来自纯概率尾。

### 1.4 资源分层

| 层 | 内容 | 供给 | 定位 |
|---|---|---|---|
| 燃料 | C / UC / R / E | 海量（挂机 + 普通包） | 熔经验、拆碎片 |
| 商品 | L / Radiant | 中低（黄金 / 璀璨 / 天穹） | 市场流通，贴回收价 |
| 资产 | Prismatic | 极低（天穹 / 棱彩尾） | 收藏，长期溢价 |
| 工时 | 等级 / 命座 / 阀门 | 系统配额 | 永远绑定 |

**为什么不再有套利**

```text
买 2 次体力 = 120 体力 = 6 次副本
成本 = 200 金币
副本金币产出 = 0
6 次副本换来的是经验 / 材料，不是金币
=> 买体力永远是“金币 → 养成进度”的单向兑换
```

## 7. 镜像卡系统

### 7.1 定位

- **本源**：玩家在 osu! 侧的身份卡，被别的玩家“抽到”后成为可交易/可上场的镜像。
- **不占主图鉴**：卡册内单开“镜像收集”Tab，不计入主图鉴 100%。
- **强独立**：`mirror-<osuId>` 是独立 `cards` 记录，与 `hero-<osuId>` 物理隔离。

### 7.2 规则表

| 项 | 规则 |
|---|---|
| 触发 | 仅非挂机包（normal / golden / radiant / sky / prism） |
| 掉率 | **1.5% / 包**，固定值，不随人数浮动 |
| 配额 | **额外第 6 张**，不占 5 张、不计/不重置保底 |
| 池子 | `card_type='mirror'` 且账号 OAuth + 已引导 + 45 天内活跃 |
| 稀有度 | 先按包型权重掷 UC–L，再从该档镜像池抽；空则逐档向下 |
| 自己 | 允许抽到自己的镜像 |
| 重复 | 允许重复抽到同一 `osuId` 的镜像卡 |
| 成长 | 普通卡公式 + 固定哈希技能模板，无个人加成 |
| 交易 | 可交易（独立 SKU） |
| 用途 | 上场 / 本体卡命座材料 / 转卖 |

**月产出**

```text
438 包 × 1.5% = 6.57 张 / 人 / 月
500 DAU → 3,285 张 / 月
活跃本体卡按 500 张算 → 每张镜像约 6.6 张 / 月
```

### 7.3 镜像稀有度权重（触发后掷）

| 包型 | UC | R | E | L |
|---|---:|---:|---:|---:|
| 普通 | 40 | 35 | 20 | 5 |
| 黄金 | 25 | 35 | 30 | 10 |
| 璀璨 | 20 | 30 | 35 | 15 |
| 天穹 | 15 | 30 | 35 | 20 |
| 棱彩 | 15 | 25 | 35 | 25 |

> 只取 UC–L：本体卡按文档封顶 L（§11.2）。若该档池为空，按 L → E → R → UC 向下兼容；
> UC 也空则不产出（开服早期人少时可能出现，属预期）。

### 7.4 数据表

```sql
-- 卡片来源：pool / hero / mirror
ALTER TABLE cards ADD COLUMN IF NOT EXISTS card_type text NOT NULL DEFAULT 'pool';
-- 镜像卡对应的 osu! 账号；池卡与本体卡为 NULL
ALTER TABLE cards ADD COLUMN IF NOT EXISTS origin_osu_id bigint;

CREATE INDEX IF NOT EXISTS cards_type_rarity_idx ON cards (card_type, rarity);
CREATE UNIQUE INDEX IF NOT EXISTS cards_mirror_origin_idx
  ON cards (origin_osu_id) WHERE card_type = 'mirror';

UPDATE cards SET card_type = 'hero'   WHERE id LIKE 'hero-%'   AND card_type = 'pool';
UPDATE cards SET card_type = 'mirror' WHERE id LIKE 'mirror-%' AND card_type = 'pool';

-- 活跃时间：镜像池按 45 天筛选
ALTER TABLE users ADD COLUMN IF NOT EXISTS last_seen_at timestamptz NOT NULL DEFAULT now();
```

镜像卡本身不需要新表：实例仍然是 `user_cards`，`card_id = mirror-<osuId>`。
经济隔离（可交易、不吃本体卡公式）由 `cards.card_type` 与 `hero_bonus = 0` 保证。

### 7.5 吞噬共鸣

**触发**：本体卡升命座时，材料选“镜像卡”。

**映射**：一张镜像只给一条属性，值 **50 bp（+0.5%）**。

```text
职业主属性：
  tank → DEF
  warrior → ATK
  mage → CRIT
  support → SPD

MOD 覆盖（取卡上第一个 MOD）：
  DT / NC → SPD
  HD / FL → CRIT
  HR / PF → ATK
  EZ / HT / NF / SD → DEF
```

**硬约束**

| 约束 | 值 | 目的 |
|---|---|---|
| 同一 `osuId` 的镜像 | **每人只能吃 1 次** | 防止囤同一张卡刷满 |
| 单属性叠加上限 | **3 次（+1.5%）** | 防止全堆 ATK |
| 总叠加上限 | **8 次（= 8 个命座槽）** | 与命座强绑定 |
| 总加成上限 | **+4%** | 微量副属性，不是第二套养成 |

**数据结构**

```sql
CREATE TABLE IF NOT EXISTS hero_resonance (
  user_id        text NOT NULL,
  source_card_id text NOT NULL,   -- mirror-<osuId>
  attribute      text NOT NULL,   -- ATK / DEF / SPD / CRIT
  value_bp       integer NOT NULL,-- 50 = +0.5%
  slot           integer NOT NULL,-- 1..8，对应第几次命座
  created_at     timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, source_card_id)
);
CREATE INDEX IF NOT EXISTS hero_resonance_user_attr_idx
  ON hero_resonance (user_id, attribute);
```

**升命座流程**

```text
POST /users/:id/cards/:heroUserCardId/constellation
  body: { materialUserCardId }
  1. 校验 heroUserCardId 属于本人且 card_type=hero
  2. 校验 constellation < 8
  3. 读取 material 的 cards 行，要求 card_type=mirror
  4. 查 hero_resonance：
       - 同一 source_card_id 已存在 → 409 duplicate_source
       - 该 attribute 已 3 条 → 只升命座，不给共鸣（不报错）
       - 总条数已 8 条 → 不再给共鸣
  5. 删除 material user_card
  6. constellation += 1
  7. 插入 hero_resonance（若通过 4）
  8. 返回 { constellation, resonance: [...], capped: boolean }
```

### 7.6 抽卡伪代码

```ts
// 只对非挂机包生效；独立随机流，不影响主卡包序列
const mirrorRandom = mulberry32((seed ^ 0x9e3779b9) >>> 0)
const triggered = pool !== "idle" && mirrorRandom() < 0.015

let bonus: DrawnCard | null = null
if (triggered) {
  const rarity = rollMirrorRarity(pool, mirrorRandom)   // 上表权重
  const card = await pickMirrorFromPool(rarity)          // 活跃 + 向下兼容
  if (card) {
    const inserted = await insertUserCard(userId, card.id)
    bonus = { cardId: card.id, rarity: card.rarity, userCardId: inserted.id, foil: false }
  }
}
// bonus 在 5 张结算之后单独返回；不写 pity、不改 counter
```
