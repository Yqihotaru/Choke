# 卡池与稀有度规则 v0.1

> 状态：基础池的算法已落地。**数值以代码为准**：`packages/shared/src/pool/score.ts`（打分、门槛、硬上限）、`rarity.ts`（占比、国榜下限）、`hero.ts`（本人卡指数）。本文讲规则怎么拼起来、为什么这样定。
> 实现：算法在 `packages/shared/src/pool/`；建池、认领、下架在 `src/pool/build.ts`（前端试验页用）；试验页 `/pool-lab`。
> 范围：基础池（Mutualify 名单）与本人卡（osu! OAuth）。签名卡不在此文。
> 配套：`经济与养成系统 v0.3.md`（卡包、分解、闪卡）。

## 1. 数据从哪来

| 项 | 来源 | 说明 |
|---|---|---|
| 玩家名单 | Mutualify 公开排行榜 `/api/rankings?offset=` | 每页 50 人，按粉丝数降序。接口公开，但外层有 Cloudflare，脚本直连会被挡 |
| 玩家名单（备选） | 第三方卡池导出（如 osugacha.com `/api/players`） | 每页 30 人，需要该站账号；导出后直接用 `normalizeMutualify` 导入 |
| 完整资料 | `scripts/sync-osu.mjs`（`pnpm sync:osu`） | client credentials 逐个拉 `/users/{id}/osu`，输出给 `/pool-lab` 导入的 JSON |
| 头像 | `https://a.ppy.sh/{id}` | 地址可按 id 拼，浏览器渲染卡面时再拉。数据源自带 `avatarUrl` 时优先用它 |
| banner | 数据源的 `coverUrl`，或 `/me/osu` 的 `cover.url` | 两种形式，都不能按 id 拼，见下 |
| 本体卡数值 | `/me/osu` | PC、TTH、等级、成就、pp、ranked set、等级分布 |

### 1.1 banner 的两种地址

```
预设封面  https://assets.ppy.sh/user-cover-presets/{presetId}/{hash}.jpeg
自定义封面 https://assets.ppy.sh/user-profile-covers/{userId}/{hash}.jpeg
```

- 预设封面是有限集合，同一张预设的 `hash` 固定，图片可以本地缓存；
- 自定义封面按用户生成，`hash` 是文件标识，换封面就变；
- 两种都必须先知道它属于谁，无法从 `userId` 推导。

因此 banner 只能来自「别人已经采集过的数据」或「本人认领」。头像不受此限制。

Mutualify 的响应里 **没有** banner、pp、ranked set、等级分布。所以：

- 基础池的稀有度只能先靠粉丝数、排名和一个 seed 定；
- ranked set / 等级分布是「本人认领后的确认项」，不是基础池的入场券；
- banner 在认领前一律显示占位。不要为了补 banner 去扫 `/users/{id}`。

`/api/friends` 与 `/api/friends/{id}` 是好友关系，默认不公开，卡池不需要，也不应拉。

## 2. 定稀有度的整条流水线

一张基础池卡的最终稀有度，按下面的顺序一步步定（`src/pool/build.ts` 的 `buildPool`）：

1. **打分**：把 pp、排名、粉丝、创作四项算成总分，再加基于 `osuId` 的确定性抖动（±1.5）（§4）。
2. **按分数排队、按占比分档**：总分从高到低排，按 seed 抖出的占比，从 Prismatic 往下依次发配额（§3）。
3. **分数门槛**：分数不够这一档的最低分，就往下压一档（§4.5）。
4. **国榜下限**：国内名次靠前的人可以被抬到下限档（§5）。
5. **pp 硬上限**：国内前 10 但 pp ≤ 8000 的人最高 L。
6. **排名硬上限**：世界排名 > 5000 最高 E。
7. **粉丝硬上限**：粉丝数 < 500 最高 E（粉丝数未知则不触发）。
8. **顶档总量上限**：L 及以上最多占全池 **8%**，超出的从总分最低、且不是被国榜下限抬上来的卡开始，降到 E（`MAX_TOP_SHARE`）。

第 5–7 条的作用：避免"纯排名很高但没人认识"或"排名高但 pp 不够"的卡被抬到 L 以上。硬上限压过国榜下限。

换 seed 会重洗落档，规则本身不变。同一 seed、同一份名单，结果完全一样。

## 3. 一个数字定占比

`sharesFromSeed(seed)` 用 mulberry32 在 `BASE_SHARE` 附近抖动 ±10%（C 档用 1 减去其余），再把"C 以外总占比"压在 95% 以内：

| 档 | 目标占比 |
|---|---|
| C | 46% |
| UC | 26% |
| R | 14% |
| E | 7% |
| L | 4.5% |
| Mythic | 2% |
| Prismatic | 0.5% |

配额用最大余数法补齐，保证总和等于人数。国榜下限会把一部分人抬上去，所以最终占比会高于这张表。

## 4. 稀有度打分

`scoreOf` 把四项各自算成 0–100，再加权求和。缺项时按剩余权重重新归一化，所以只有排行榜数据的数据源也不会被系统性压低。

| 项 | 权重 | 数据来源 |
|---|---|---|
| 排名 | 38 | `global_rank` + 国内名次 |
| pp | 30 | 排行榜或 `/users` |
| 粉丝 | 24 | Mutualify |
| 创作（谱面数 + GD） | 8 | `/users`，只做附加分 |

```
总分 = Σ(分项 × 权重) / Σ(已出现项的权重)
```

### 4.1 pp

```
< 2000   15 × log10(1+pp) / log10(2001)
≥ 2000   15 + 85 × (log10(pp) − log10(2000)) / (log10(13000) − log10(2000))
```

参考值：2000 ≈ 15，4000 ≈ 45，6000 ≈ 64，8000 ≈ 78，9600 ≈ 86，13000 = 100。

### 4.2 排名

国内名次给基准分，乘国家系数，再被世界排名的上限封顶：

```
排名分 = min(国内分 × 国家系数, 世界上限)
```

- 只有世界排名时，直接取世界上限；只有国内名次时，取基准分。
- 国内分从 1–5 名 100 分，一路降到 5000 名外 8 分，名次越靠前分档越细（`countryRankScore`）。
- 世界上限从前 10 名 100 分，降到十万名外 8 分（`worldCeiling`）。
- 国家系数按该国在榜人数：≥ 1000 为 1.0，500–999 为 0.85，200–499 为 0.7，50–199 为 0.55，不足 50 或未知为 0.4。

效果：大国第 500 仍有 52 分；3 人小国的第 1 被国家系数和世界上限一起压住，不会因为"全国第一"就变 Mythic。

### 4.3 粉丝

| 粉丝 | 分 |
|---|---|
| < 100 | 0–20，按 log |
| 100–299 | 20–40 |
| 300–499 | 40–55 |
| 500–999 | 55–75 |
| ≥ 1000 | 75 + 25 × log10(f/1000)，10000 ≈ 100 |

档内线性，档间留 15–20 分的台阶。

### 4.4 创作

谱面数和 GD 数合成一项，GD 按 1.5 倍算：

```
创作分 = 100 × log10(1 + 谱面数 + 1.5 × GD 数) / log10(501)
```

约 10 张 ≈ 40，100 张 ≈ 74，500 张 = 100。两项都没有数据时不参与归一化。

### 4.5 分数门槛

配额仍由 seed 决定，但加一道分数门槛：分数不够就不给这一档，往下压到够为止。

| 档 | 最低分 |
|---|---|
| Prismatic | 85 |
| Mythic | 75 |
| L | 65 |
| E | 52 |
| R | 38 |
| UC | 25 |
| C | 0 |

### 4.6 缺数据时

- 只有排行榜：pp + 排名两项，权重归一化后占满 100%，粉丝和创作不参与。
- 加上 Mutualify：多出粉丝项。
- 再跑 `/users` 或玩家认领：创作项补齐，四项齐全。

## 5. 国榜下限

| 国内名次 | 下限 | 生效条件 |
|---|---|---|
| 1–10 | Mythic | 该国有排名玩家 ≥ 10 |
| 1–50 | L | ≥ 50 |
| 1–125 | E | ≥ 125 |
| 1–300 | R | ≥ 300 |

「有排名」指 Mutualify 返回的 `globalRank` 非空。名次按各国 `globalRank` 升序排，粉丝数只做同分决胜。国家人数不够时该档不生效，避免 3 人小国整国变 Mythic。

**副作用**：固定名次的下限会把一部分人抬上去，让 R 及以上的实际占比高于 §3 的目标，国家越多越明显。想压低，就调 `COUNTRY_FLOORS` 里的名次或去掉 R 档；`MAX_TOP_SHARE`（§2 第 8 条）只限 L 以上，不管 R。

## 6. 本人卡

**获取方式**：登录时只生成 `hero-{osuId}` 的卡定义，不写入卡册；完成新手引导（OOBE）后发放新手礼包（含 1 个神秘卡包，数量见《经济与养成系统 v0.3》§4.2），打开背包里的神秘卡包才真正获得本体卡。邮箱注册的账号没有 osu! 数据，不发神秘包。

**稀有度**：本体卡取公开池卡（`pool-{osuId}`）的稀有度，再套两条硬上限，最后封顶 L（`apps/api/src/hero.ts`）：

- 世界排名 > 5000 → 最高 E；
- osu! 粉丝数 < 500 → 最高 E；
- 初始品质一律封顶 **L**，满养成后才走向更高强度，避免开服即终局。

稀有度只看公开排行榜，个人数据（`/me/osu`）不参与稀有度，也不参与强度。这样池卡 R，本体卡也是 R，不会因为登录换一套算法就变成 L。

**本体卡的成长**：等级上限 12、命座上限 8，命座材料是镜像卡并带"吞噬共鸣"（见《经济与养成系统 v0.3》§6.2、§7.5）。

**`heroIndex`（只在试验页用）**：`hero.ts` 里的 `heroIndex` 把 `/me/osu` 的 PC、TTH、等级、成就、ranked set、等级分布、pp 算成一个指数，`/pool-lab` 的"认领"用它展示。**服务端没有接它**：

- 稀有度不用它；
- 数据库里的 `hero_bonus` 列目前是 0，没有任何代码读写；
- 早期设计过"OOBE 前 −20%、OOBE 后最高 +20% 的个人加成"，**没有实现，也不打算按原样实现**。要不要做个人加成，等有了明确需求再定。

## 7. 闪卡、碎片与市场

规则细节和数值以《经济与养成系统 v0.3》§5 为准，这里只记与卡池相关的几条：

- 闪卡是 `user_cards` 的实例属性，不改变 `cards.rarity`，任何卡都可能出闪。
- 闪卡率按卡包，写在 `content/packs.json`。
- 分解任意非本体卡，得**同品质碎片**（固定 4 片，每片折算一笔经验）；碎片可以喂任何卡。
- **只有闪卡**在分解或被喂掉时额外给精华；精华只用来给已有卡镀闪，不参与升级或市场。
- 市场用金币交易，规则见经济文档 §8。

## 8. 下架

`revoke(card)` 只写 `hidden: true`，同时清掉 `hero` 和认领状态。

- 抽卡和浏览都跳过 `hidden`；
- 重新导入同一份名单时，`buildPool` 按 `osuId` 保留旧行，已下架的人不会被放回来；
- 恢复上架只翻 `hidden`，不需要重新计算。

目前下架只存在于试验页的内存里，**服务端还没有对应的下架状态**（见 §10）。

## 9. 第三方卡池的做法（观察记录）

osugacha.com 的 `/api/players` 每页 30 人，返回字段可以直接映射到 `MutualifyRow`：

| 字段 | 用途 |
|---|---|
| `id` / `username` / `countryCode` | 身份 |
| `avatarUrl` | 带缓存戳的头像地址 |
| `coverUrl` | 预设或自定义封面 |
| `followerCount` | 主信号 |
| `mappingFollowerCount` | 谱面关注数 |
| `rankedMaps` / `guestMaps` / `lovedMaps` | 作图数量 |
| `popularity` / `pp` / `globalRank` | 热度与强度 |
| `lastSyncedAt` | **后端同步时间** |
| `currentRarity` / `mintedCount` | 他们自己的发行状态 |

`lastSyncedAt` 说明他们不是前端拼地址，而是后端定期调 osu API 同步每个玩家，把 `avatarUrl`、`coverUrl` 和上面这堆信号落库。卡面只是读库。

这份抓包的价值是字段设计，不是数据本身：抓包工具会截断长响应，拿不到完整分页，而且对方的限流约 300 次/窗口。

## 10. 目前没做的

| 缺口 | 原因 | 需要什么 |
|---|---|---|
| 未认领卡的 banner | 需要先知道封面地址 | 跑 `scripts/sync-osu.mjs`，`cover.url` 会写进 `coverUrl` |
| 基础池的 ranked set / 等级 | 需要逐个读用户 | 同上，脚本会填 `rankedMaps` / `guestMaps` / `lovedMaps` / `grades` |

| 国榜名次的跨期稳定 | 名次随池子人数变 | 固定快照日期，或在库里存 `snapshot_at` |
| 本体卡个人加成 | 早期设计，没有实现 | 要不要做先定，见 §6 |
