# Choke! 架构重整 v0.1

> 状态：进行中。本文记录目标结构、依赖规则与分阶段进度，作为后续拆分的唯一依据。
> 基线：`master` @ 2026-11-19。

---

## 1. 目标结构

```
apps/
  web/        玩家端（现在的 src/，Vite 根）
  lab/        卡面实验室 / 卡池实验室 / 全息参考（不进主包）
  api/        Fastify + PGlite
packages/
  shared/     类型 + 配置 + 纯规则（前后端共用，零 React）
```

**依赖方向（单向，不可逆）**

```
apps/web ─┐
apps/lab ─┼─> packages/shared
apps/api ─┘
```

三条硬规则：

1. `packages/shared` 不出现 React / DOM / window / fetch。
2. `apps/api` 不允许出现 `../../../../src/...`。
3. `apps/lab` 可以 import `apps/web`，反之禁止。

## 3. 下一阶段要点

### 阶段 1：packages/shared（已完成）

`packages/shared/src` 现有模块：

```
types.ts         Rarity / Element / Job / CardFaceData / CardSkill / CardSkillRef
skills.ts        技能注册表、14 子职业、旧名别名、skillId 解析
config.ts        DECK_SIZE / PACK_SIZE / MARKET_UNLOCK_LEVEL / POOL_IDS
                 RARITY_BASE / CONSTELLATION_BONUS / MAX_SUPPORT_SLOTS
progression.ts   等级、命座、经验、熔卡
economy.ts       精华、闪卡、市场价
pool/            types / score / rarity / hero（卡池构建与本体卡计算）
tutorial.ts      教程步骤枚举
```

`src/card/*`、`src/pool/*`、`src/tutorial/*` 对应文件都改成一行 re-export，**现有 import 全部零改动**。
`apps/api` 不再出现任何 `../../../../src/...` 或 `../../../src/...`。

### 阶段 3：skillId（已完成）

- 卡面类型新增 `skillRefs?: CardSkillRef[]`，`skillRefs` 存在时优先于旧的 `skills`。
- `cards.skill_refs jsonb` 由 `migrations/0001_skill_refs.sql` 建列，`schema.ts` 同步。
- 导入新卡时 `import-cards.ts` 自动写 refs；存量卡用 `apps/api/scripts/backfill-skill-refs.ts` 回填（幂等，`--force` 重算）。
- 老卡保留 `ref.name`，显示名不变；行为与费用一律取注册表。

### 阶段 5：fetch 收口（已完成）

- `src/desk/api.ts` 扩成完整客户端：认证 / 卡包 / 卡牌详情 / 图鉴 / 教程进度 / 市场 / 养成。
- 新增 `ApiError`（带 `code`），调用方可以按机器码分支（如 `no_packs` / `invalid_token`）。
- **`src` 下除 `api.ts` 外已无任何 `fetch(` 调用**（17 处全部收口）。

## 4. 运维脚本

| 脚本 | 用途 |
|---|---|
| `apps/api/scripts/backfill-skill-refs.ts` | 把 `cards.skills`（名字）翻译成 `skill_refs`（id）；幂等，`--force` 重算 |
| `apps/api/scripts/reset-players.ts --yes` | 清空所有玩家数据，保留 `cards`；重置 public_id 序列 |

两个脚本都要求先停 API（PGlite 单进程）。
