# 任务与签到前端对接清单 v0.1

给 fable：任务、签到界面要用到的后端接口。规则都在服务端判定，前端只负责显示和点按钮。全部接口需要登录，且只能操作自己的账号（`:userId` 必须是自己）。

返回格式统一：成功 `{ ok: true, data }`，失败 `{ ok: false, error: { code, message } }`。类型在 `@choke/shared/quests`（`QuestsOverview`、`QuestView`、`SignInDayView`）。

## 1. 接口

| 接口 | 作用 |
|---|---|
| `GET /users/:userId/quests` | 总览：全部任务、进度、能否领取、重置时间、活跃点、签到日历 |
| `POST /users/:userId/quests/:questId/claim` | 领一条任务的奖励 |
| `POST /users/:userId/quests/claim-all` | 一键全领（所有已完成没领的） |
| `POST /users/:userId/sign-in` | 今天签到 |

没有推送：任务做完不会主动通知。需要红点时进入主界面 / 回到页面时拉一次 `GET quests`，看 `data.claimable`（可领的条数）。

## 2. 总览 `QuestsOverview`

- `now`：服务器现在的时间。倒计时用 `resets` 减 `now`，不要用本机时间。
- `resets.daily / weekly / monthly`：三个周期下一次重置的时间（日常每天 4:00，周常周一 4:00，月常每月 1 日 4:00，北京时间）。
- `quests[]`：每条任务
  - `id`、`period`（`daily` / `weekly` / `monthly`，按它分三个标签页）、`name`、`desc`
  - `target` / `progress`：进度条
  - `claimable`：完成了还没领 → 显示「领取」按钮
  - `claimed`：已领 → 灰掉打勾
  - `rewards[]`：`{ kind, label, count }`，直接渲染图标和数量（`kind` 是 `coins` / `essence` / `stamina` / `item` / `pack`）
  - `points`：完成后给的活跃点
- `points.daily / weekly / monthly`：`{ earned, total }`，已领取任务的活跃点 / 该周期满分，做活跃点进度条。
- `claimable`：整体可领条数，主界面红点。
- `signIn`
  - `monthKey`（`2026-11`）、`today`（本月第几天，每月 1 日 4:00 才算第 1 天）
  - `signedToday`：今天签了没有 → 控制「签到」按钮
  - `signedDays`：本月已签几天
  - `days[]`：本月每一天 `{ day, rewards[], signed, special }`，画签到日历；`special` 是有特别奖励的日子，可以做高亮。**没签的过去日子不能补签**，不要给按钮。

## 3. 领取

- 领单条：成功返回 `{ questId, rewards[] }`。
- 一键全领：返回 `{ claimed: [questId...], rewards[] }`，`rewards` 是已经合并过的总额（同种道具相加），直接弹一个「获得」面板。`claimed` 为空表示没有可领的（不是错误）。
- 签到：返回 `{ day, rewards[] }`。签到会顺带让「完成一次签到」这类日常任务变成可领，成功后重新拉一次总览。
- 领取后金币、道具、卡包数量变了，记得刷新对应的钱包 / 背包显示。

## 4. 错误码

| code | 什么时候 |
|---|---|
| `not_done` | 任务还没完成（400） |
| `already_claimed` | 这一周期已经领过（400）；多次点击或多开页面时会遇到，提示后刷新总览即可 |
| `already_signed` | 今天已经签过（400） |
| `not_found` | 没有这个任务 id（404） |

## 5. 前端要注意的事

1. 不要自己判断「今天是几号 / 该不该重置」。以 `now`、`resets`、`signIn.today` 为准，4:00 换日的边界在服务端。
2. 页面开着跨过了重置点：倒计时到 0 时重新拉一次总览。
3. **周期结束时没领的奖励不会丢**：已完成的会在下次读取任务时以邮件发到邮箱（标题「任务奖励补发」），未完成的作废。建议在界面上写一行提示：「任务在重置前请及时领取，完成未领的奖励会随邮件补发，未完成的进度会清零」。
4. 任务内容（名字、目标、奖励）全部来自服务端的 `content/quests.json`，不要在前端写死。数值目前是占位，之后会调。
5. 活跃点现在只是显示用的数字，还不能兑换任何东西（通行证以后做）。
