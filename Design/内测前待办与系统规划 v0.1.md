## 二、推荐执行顺序（按依赖与风险分 4 个波次）

> 为什么不能乱序？因为 **周本产金币（+16,000/月）** 如果先于 **MOD / 技能升级耗金币（-13,800/月）** 开放，经济会直接失衡；而 **CR 的 P0 并发漏洞** 不先修，后面加新养成入口会继续复制隐患。

### 第一波：清雷 + 补战斗底盘（预计耗时最短、立竿见影）
1. **修完 `CodeReview清单 v0.1.md` 中的 P0 / P1**（保住并发事务安全与卡片 UI 不崩）。
2. **完成 B1（战/法/坦/辅元素技能补全）+ B2（共鸣进战斗面板）**，重录基准并跑通全量测试。

### 第二波：材料副本 + 进阶 + 阀门（打通养成素材流）
3. **落地 A1（进阶材料 + 进阶材料本 + 难度/扫荡底层）**。
4. **落地 A2（40/50/60/70 突破阀门材料接入）** —— 先由测试/任务占位或直接接第三波周本产出来验证。

### 第三波：周本 + 两大金币大出口（经济成对闭合）
5. **同时设计并落地 A3（周本 5 档）+ A4（MOD 装备与升星 + 模组本）+ A5（技能 Lv1–5 升级）+ A6（定向兑换）**。
6. 跑一轮完整的**月度金币 / 碎片 / 体力 / 阀门四维收支平衡验算**，确保与 `经济与养成系统 v0.3.md` 的紧平衡目标（+5%～+10% 净沉淀）对齐。

### 第四波：内容 + 前端大合龙 + 闭门踩雷
7. **补全 C1/C2（第 1 章 40+ 节点长图 + osu! 梗事件 + 远征真浏览器全流程）**。
8. **接通全部 D 类前端入口与扁平化 UI / 介绍页**。
9. 找 2～3 个熟人做**闭门踩雷测试** → 修完最后毛刺 → 迁上服务器开启内测。

### 4.2 后端新发现

**P0 / P1（建议随第一波一起修）**
- 已读确认：`removeUserCard` 取消在售挂单时**不退押金**（`progression.ts`）。喂养、融合、分解、批量分解、NPC 回收都会触发。修法：改状态时 `.returning()` 拿押金退还并记 `market-deposit-refund` 流水；或在售的卡直接拒绝这些操作（与 `reroll-skill` 的 `card_listed` 一致，推荐后者）。
- 说明：`shop.ts` 和 `reroll-skill` 没有功能门是**故意的**（测试期不锁，等整理玩家流程时再放进第一天的解锁进度），不算问题。
- 已读确认：批量分解选中出征中的卡，会因 `in_expedition` 让整批（最多 60 张）回滚；批量分解不检查在售，与 `reroll-skill` 不一致。
- 待复核：`/market/listings`、`/market/history` 没有登录和功能门；`listings` 每次访问还会开一个写事务做过期清理。修法：加门，过期清理改低频。
- 待复核：`/users/:userId/cards`、`/codex` 的排序没有 `id` 兜底，同一包开出的卡 `obtainedAt` 相同，翻页会重复或漏卡。这是重复 key 警告的头号嫌疑。修法：排序末尾追加 `id`。
- 待复核：邮件一键领取，任何一封附件发放失败会让整批回滚，坏邮件总排在最前面，永远领不了。修法：每封用嵌套事务，失败的跳过。

**P2**
- 待复核：上架没有 `lockUser`，检查都在事务外。并发上架得到 500 而不是 `already_listed`；上架与出征同时发生，同一张卡可能既在售又在出征。
- 待复核：`error-handler.ts` 对非业务错误直接 `reply.send(error)`，格式不统一，5xx 可能带出 SQL 文本。
- 待复核：`/dev/mails` 只靠 `NODE_ENV !== production` 控制，漏设就开着。建议改成显式开关，默认关。
- 待复核：新手包"最后一包保底"判断与扣包不在同一事务，并发开包可多触发保底（推演，未实测）。
- 待复核：神秘包领本体卡不在事务里，发放失败会白扣；买家卖家互买可能死锁；成交税对 20 以下低价单为 0；任务过期补发邮件合并后可能超过邮件校验上限。
- 待复核：`maxStars` 对含休息、宝箱等节点的模板图是估算值，星级档位可能偏。
- 体力药水在体力 661～719 时只加到 720 仍扣满 100 金币（antigravity 已报同类）。

### 4.3 前端与战斗新发现

- **快速连点"结束回合"，动画错乱**（用户确认）：新一步到来时，上一步没播完的计时器不会被取消，两批动画事件交叉播放。修法：新 `actionSeq` 到来时清掉旧计时器，或播放期间锁定"结束回合"按钮。位置 `src/battle/view/BattleStage.tsx`、`src/battle/view-modern/BattleStage.tsx`。
- **镜像卡（第 6 张）前端没演**：服务端已发卡并记流水，`OpenPackResult` 没用 `bonus`，开包动画里没有。
- **重复 key 警告来源未确认**：先修分页排序兜底，再用浏览器抓组件栈。
- 切号后背包、市场面板先显示上一个账号的数据（给面板加 `key={userId}` 最省事）。
- 多处 `.catch(() => {})` 吞错：`BattlePanel`、`MailBox`、`AccountPanel`、`useDeskSession`。
- `BattlePanel`、`CardDetail` 用 `ITEMS[id].name` 查表没有兜底，遇到新道具会白屏。
- 前端几乎不按 `error.code` 分支，`feature_locked`、`in_expedition`、`already_listed` 等只靠 message 显示。
- 市场下架按钮在交易未解锁时仍可点。
- 已排除：`BattleStage` 的 hooks 顺序报错是热更新残留，代码本身没问题；远征服务端的跳格、重复领奖、重复结算、并发、地图生成死循环，均未发现问题。

### 4.4 新增任务（插入第一波，在 CR 修复之后、B1/B2 之前）

1. **挂机包改按时间累计**（规则已定）：
   - 从注册之后开始算，**在线才累计**，每在线 1 分钟得 1 个。
   - **在线判定**：玩家正常上线时前端先发一次请求，服务端据此知道开始在线；之后每隔 **20～40 秒**（随机抖动，避免所有人同一秒发）发一次心跳；关掉标签页没有请求时，靠心跳超时（暂定 90 秒无请求）判为离线。心跳同时用来显示玩家在线状态。
   - **每日额度**：每天北京时间 4:00 重置（复用 `reset.ts` 的 `resetDayKey`）；当天累计满额度后不再增长。额度取 60～180，原因是经济整体要按比例放大，新玩家不能上来没东西玩；具体取值等经济演算后定。
   - 实现要点：用户表加最后在线时间；记每日在线累计分钟；`packs.ts` 的领取改为"已累计 − 已领取"；心跳每次只按"距上次不超过 60 秒的间隔"计入，防止离线很久后一次性补发。2. **卡包额度放宽 + 经济重新演算**：以 `经济与养成系统 v0.3.md` 为基线，重算卡包日、周、月产出，碎片和金币回收，以及对第三波"周本 + MOD + 技能升级"闭合的影响。
3. **市场模拟测试**：用脚本模拟多名玩家在上架、成交、税、押金、价格带（±40%）规则下运行一段时间，观察金币通胀、价格带被小号刷价（无成交记录的卡不限价）、押金与税的回收速度。放进 `apps/api/scripts/`，纳入 `pnpm test` 前先单独跑通。
