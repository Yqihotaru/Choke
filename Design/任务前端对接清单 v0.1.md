# 成就与签到前端对接清单 v0.1

> 2026-11-28 改写：日常、周常、月常任务和活跃度宝箱已经删除（见 `设计原则与方向 v0.1.md` §5），只剩**一次性成就**和**每日签到**。文件名没改，免得别处的引用断掉。

给 fable：成就、签到界面要用到的后端接口。规则都在服务端判定，前端只负责显示和点按钮。全部接口需要登录，且只能操作自己的账号（`:userId` 必须是自己）。

返回格式统一：成功 `{ ok: true, data }`，失败 `{ ok: false, error: { code, message } }`。类型在 `@choke/shared/quests`（`QuestsOverview`、`QuestView`、`SignInDayView`）。

## 1. 接口

| 接口 | 作用 |
|---|---|
| `GET /users/:userId/quests` | 总览：全部成就、进度、能否领取、签到日历 |
| `POST /users/:userId/quests/:questId/claim` | 领一条成就的奖励 |
| `POST /users/:userId/quests/claim-all` | 一键全领：所有完成了没领的成就 |
| `POST /users/:userId/sign-in` | 今天签到 |

没有推送：成就做完不会主动通知。需要红点时进入主界面 / 回到页面时拉一次 `GET quests`，看 `data.claimable`（可领的成就条数）。

## 2. 总览 `QuestsOverview`

- `now`：服务器现在的时间。
- `quests[]`：每条成就
  - `id`、`name`、`desc`
  - `group`：可选的小标题（成长 / 收集 / 养成 / 远征 / 日常），成就页按它分栏
  - `target` / `progress`：进度条
  - `claimable`：完成了还没领 → 显示「领取」按钮
  - `claimed`：已领 → 灰掉打勾
  - `rewards[]`：`{ kind, label, count }`，直接渲染图标和数量（`kind` 有 `coins` / `essence` / `item` / `pack` / `playerExp`）
- `claimable`：可领的成就条数，主界面红点。
- `signIn`
  - `monthKey`（`2026-11`）、`today`（本月第几天，每月 1 日 4:00 才算第 1 天）
  - `signedToday`：今天签了没有 → 控制「签到」按钮
  - `signedDays`：本月已签几天
  - `days[]`：本月每一天 `{ day, rewards[], signed, special }`，画签到日历；`special` 是有特别奖励的日子，可以做高亮。**没签的过去日子不能补签**，不要给按钮。

**成就不重置、不过期、没有倒计时**，没领的一直留着。**没有周期标签页了**，只有一个成就列表。

## 3. 领取

- 领单条：成功返回 `{ questId, rewards[] }`，成功后重新拉一次总览。
- 一键全领：返回 `{ claimed: [questId...], rewards[] }`，`rewards` 是**合并过的总额**（同种道具相加），直接弹一个「获得」面板。`claimed` 为空表示没有可领的（不是错误）。
- 签到：返回 `{ day, rewards[] }`。签到会顺带给「新手四日补给」这类成就记一笔，成功后重新拉一次总览。
- 领取后金币、道具、卡包数量变了，记得刷新对应的钱包 / 背包显示。

## 4. 错误码

| code | 什么时候 |
|---|---|
| `not_done` | 成就还没完成（400） |
| `already_claimed` | 已经领过（400）；多次点击或多开页面时会遇到，提示后刷新总览即可 |
| `already_signed` | 今天已经签过（400） |
| `not_found` | 没有这个成就 id（404） |
| `feature_locked` | 功能还没解锁（现在 `quests` 功能是 Lv3；解锁方式以后会改成随引导） |

## 5. 前端要注意的事

1. 不要自己判断「今天是几号」。以 `signIn.today` 为准，每天 4:00 换日的边界在服务端。
2. 成就内容（名字、目标、奖励）全部来自服务端的 `content/quests.json`，不要在前端写死。数值目前是占位，之后会调。
3. 旧版本留下的日常 / 周常进度行还在数据库里，但接口不会再返回，前端不用管。

## 6. 每日推荐谱面（osu!）

每天（4:00 换）有 1 张推荐谱面。玩家在 osu! 里打过之后回游戏点「检查」，服务端去 osu! 读他的成绩。**目前通过之后没有奖励**：原来的日常任务 `daily-osu-beatmap` 已经删了，服务端仍会记一次 `osu-daily-pass` 事件，以后只发外观类奖励或成就，接上时在 `content/quests.json` 里加一条成就即可，不用改代码。类型在 `@choke/shared/osu-daily`（`OsuDailyView`、`OsuDailyCheckResult`）。

| 接口 | 作用 |
|---|---|
| `GET /users/:userId/osu-daily` | 今天的推荐谱面 |
| `POST /users/:userId/osu-daily/check` | 点「检查」 |

`GET` 返回 `OsuDailyView`：
- `beatmap`：`{ beatmapId, title, url, minAccuracy?, minRank? }`；`url` 是谱面页面链接，做「去 osu! 打」按钮；今天没有推荐谱面（池子空了）时为 `null`，整块隐藏。
- `minAccuracy`（百分数，如 95）和 `minRank`（`D` / `C` / `B` / `A` / `S` / `SS`）**只有谱面设了条件才出现**，出现时在谱面名下面写「准度 ≥ 95%」「评级 ≥ S」。没出现就是不限，只要 Pass 就行（挂 NF 也算）。
- `passed`：今天已经通过。
- `cooldownSeconds`：距离下次能点「检查」还要几秒，按钮做倒计时用；0 表示现在可以。
- `day`、`resetsAt`：今天的日期和下次换谱面的时间（ISO）。

`POST check` 返回：
- `{ passed: true, alreadyPassed }`：通过了（`alreadyPassed` 为 true 表示之前已经通过，没有再去查）。
- `{ passed: false, reason: "no-score" }`：今天还没找到这张谱面的成绩（或者没 Pass）。提示「还没找到你今天在这张谱面上的成绩，打完后稍等一会儿再检查」。
- `{ passed: false, reason: "not-good-enough", found }`：找到了成绩但没达到条件（准度 / 评级不够，或这条成绩已经用过）。

错误码：

| code | 状态码 | 什么时候 |
|---|---|---|
| `osu_not_linked` | 400 | 玩家是邮箱账号，没有绑定 osu!。提示「需要用 osu! 账号登录才能检查成绩」 |
| `no_osu_daily` | 404 | 今天没有推荐谱面 |
| `cooldown` | 429 | 点得太快；错误里带 `cooldownSeconds` |
| `osu_busy` | 429 | 全服查询太多，稍后再试；带 `cooldownSeconds` |
| `osu_unavailable` | 503 | osu! 暂时连不上，稍后再试（不占冷却） |

注意：成绩的结束时间必须在今天 4:00 之后；只认 osu! standard 模式；同一条成绩只能用一次；点「检查」之后有 60 秒冷却，请把冷却显示在按钮上，别让玩家连点。
