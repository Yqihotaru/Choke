## 1. 现在的结构与依赖规则

```
src/            玩家端前端（Vite 根，React）。含 src/lab/（卡面实验室等试验页）
apps/
  api/          Fastify 服务端：路由、事务、迁移、测试脚本
packages/
  shared/       类型 + 配置 + 纯规则（前后端共用，零 React）
content/        游戏内容（JSON）：战斗、地图、事件、掉落、任务、进度表
```

最早的目标是把前端拆成 `apps/web` 和 `apps/lab` 两个包。**这个没做，也不打算做**：前端留在根目录 `src/`，试验页放 `src/lab/`，不进主流程。

**依赖方向（单向）**

```
src ──────┐
apps/api ─┴─> packages/shared
```

三条硬规则（现在都成立）：

1. `packages/shared` 不出现 React / DOM / window / fetch。
2. `apps/api` 不允许出现 `../../../src/...`（服务端不引用前端代码）。
3. 前端所有网络请求都走 `src/desk/session/api.ts`（音效清单和 `src/lab/` 的试验页除外，它们读的是静态文件）。

`packages/shared/src` 现有内容：

| 位置 | 内容 |
|---|---|
| `types.ts`、`card-def.ts`、`config.ts` | 类型、卡牌定义、全局常量 |
| `skills.ts`、`skill-check.ts` | 技能表、发牌、校验 |
| `progression.ts`、`economy.ts`、`stamina.ts`、`items.ts`、`dungeons.ts` | 养成、经济、体力、道具、副本 |
| `ledger.ts`、`mail.ts`、`quests.ts`、`quest-content.ts`、`osu-daily.ts` | 流水、邮件、任务 |
| `lineup.ts`、`expedition-points.ts`、`expedition/` | 卡组、远征点数、远征 |
| `battle/` | 战斗：`config`、`rules`、`engine`、`ai`、`actions`、`stars`、`content`、`types` |
| `pool/` | 卡池算法：`score`、`rarity`、`hero` |
| `rng.ts`、`player.ts`、`reset.ts`、`resonance.ts`、`tutorial.ts` | 种子随机、玩家、重置时间、共鸣、教程步骤 |

`src/card/`、`src/pool/`、`src/tutorial/` 里与 shared 重名的文件只是一行 re-export，前端老的 import 不用改。

## 2. 当时的分阶段与结果

| 阶段 | 内容 | 状态 |
|---|---|---|
| 0 | 战斗演出：逐段伤害事件 + 血条投影 | ✅ |
| 1 | `packages/shared` 落地，依赖方向掰正 | ✅ |
| 2 | 数据库迁移系统，`schema.ts` 单一类型来源 | ✅ |
| 3 | skillId 化（技能独立于卡面） | ✅ |
| 4 | 战斗 `config` / `rules` / `engine` / 视图 四拆 | ✅ |
| 5 | fetch 收口到 `api.ts` | ✅ |
| 6 | `DeskPage` 拆分 + 事件总线收口 | 🟡 只做了一半 |
| 7 | lab 搬出 `src/card`，死代码清理 | ✅ |

各阶段留下的、现在仍然有效的规矩：

- **战斗演出**：引擎每一段伤害单独发事件，带 `hpAfter` / `enemyHpAfter` 快照；视图用"已播放事件"推进血条，不直接读引擎终值。引擎同步、确定、可回放，服务端用同一份引擎校验。
- **迁移**：`apps/api/migrations/*.sql` 是**运行时结构真相**，按文件名顺序执行，记录在 `schema_migrations`（现有 16 个，最新 `0015`）；`apps/api/src/db/schema.ts` 是**类型真相**（Drizzle 查询用）。改表 = 改 `schema.ts` + 新增 `migrations/00NN_xxx.sql`，不要往 `client.ts` 里堆 `ALTER`。
- **skillId**：卡上只存技能 id（`cards.skill_refs`），名字、费用、行为一律取技能表；认不出的 id 报错。早期的 `cards.skills` 老列已在 `0006_drop_card_skills.sql` 删除，回填脚本也已删，不再有回落。
- **fetch 收口**：`src/desk/session/api.ts` 是完整客户端，带 `ApiError`（有机器码 `code`，调用方按码分支，如 `no_packs` / `invalid_token`）。
- **战斗四拆**：`config.ts`（数值）、`rules.ts`（纯函数：Combo / 减伤 / 防御档位 / 相克 / 威胁度）、`engine.ts`（状态机 + 事件流）；现在都在 `packages/shared/src/battle/`，视图在 `src/battle/`。`rules.ts` 不出现 `state`，可被服务端直接复算。
- **lab 搬家**：卡面实验室和六个卡面版本在 `src/lab/faces/`，现用的卡面是 `CardFaceB2`（见《卡面设计交接》）。`public/holo-lab/` 保留备用；`src/components/theme-provider.tsx` 等亮色主题接入。

数据库：线上和开发都用真 PostgreSQL（`DATABASE_URL`），**PGlite 只在测试脚本里用**（`PG_DATA_DIR`，一次性临时库，是 devDependency）。大改动后、合并或上线前跑 `pnpm test:pg`。

## 3. 还欠的（阶段 6）

- **`DeskPage.tsx` 约 1900 行**：拖拽 / 落点判定与开包流程还没抽成 hook（`useDeskDrag`、`usePackOpening`）。这两块和飞行动画、布局 ref、定时器强耦合，要人工点一遍桌面才能验证。
- 已经做完的部分：桌面事件名集中在 `src/desk/session/events.ts`（悬停合并为 `DESK_HOVER_EVENT`，数据变化合并为 `DESK_DATA_CHANGED_EVENT`）；账号、钱包、卡包库存、刷新与登出抽到 `useDeskSession.ts`。
- 配置还有少量前端兜底值（`?? 5` / `?? 7`）与服务端配置重复，随上面一起清。

这一块**等手机端 UI 重构一起做**：桌面页面本身要重做，现在拆它不划算（见《备忘录》）。

## 4. 运维脚本

| 脚本 | 用途 |
|---|---|
| `apps/api/scripts/reset-players.ts --yes` | 清空所有玩家数据，保留 `cards`；重置 public_id 序列 |
| `apps/api/scripts/import-cards.ts` | 导入卡池（整表替换卡定义，先停 API），自动写 `skill_refs` |
| `apps/api/scripts/db-info.ts` | 看当前连的是哪种库、迁移目录和文件 |
| `pnpm admin:set <用户 id 或 osu! id> [--off]` | 设置 / 撤销管理员（唯一能改管理员标记的地方） |

跑破坏性脚本前先确认连的是哪个库。
