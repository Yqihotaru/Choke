## 0. 已拍板的规则（2026-11-22）

| 项 | 结论 |
|---|---|
| 融合 | 同名卡互吃，只提升命座 |
| 喂养 | 任意卡折算成经验喂给目标卡（基准 100%） |
| 分解 | 卡 → 若干个**同品质**碎片；碎片既是通用材料，也能当经验喂卡，约八折 |
| 经验道具 | 只从经验本掉；按体力折算要比喂卡更划算 |
| 已升级卡的返还 | 分解或被喂掉时，按投入经验的约 75% 返还**经验道具**（大/中/小拆分，尾数舍去） |
| 经验量级 | 所有经验数值整体 ×10（需求、卡、碎片、道具、副本同一次迁移），并切到 v0.3 §6.1 的表 |
| 强化界面 | 单独做：目标卡 + 卡/碎片/道具三栏多选 + 升级预览 |
| 种子 | 每次出征一个种子；各处按名字派生独立随机流（`map`、`battle-N/enemy`、`battle-N/player`），不存小种子 |
| 我方随机 | 暴击、伤害浮动、boost、必杀、连击、buff 随机选目标，全部走 `battle-N/player` |
| 提交 | 每回合把操作追加到服务端；刷新从服务端记录恢复；每场战斗结束由服务端复算并锁定；出征结束统一结算 |
| 重开 | 不能重开单场战斗，只能放弃或撤退整个出征 |
| 重置时间 | 北京时间 04:00（日常、签到）；周一 04:00（周常）；每月 1 日 04:00（月常） |

## 1. 三层

| 层 | 放在哪 | 内容 | 规则 |
|---|---|---|---|
| 规则 | `packages/shared` | 战斗引擎、伤害公式、AI 行为原语、条件求值、地图生成器 | 纯函数，无 IO，不 import 任何具体内容 |
| 内容 | `content/`（仓库根目录） | 敌人、遭遇、地图、剧情、掉落表、副本、卡包、任务 | 纯 JSON，由 `packages/shared` 里的 zod schema 校验 |
| 状态 | 数据库 | 玩家拥有什么、走到哪、领过什么 | 只存 id 引用内容，不存内容本身 |

引擎拿内容当参数：`createBattle(encounter, deck, rng)`，而不是 `if (presetId === "xxx")`。

## 2. 目录

```
content/
  enemies/          # 单个敌人：数值、属性、弱点、AI
  encounters/       # 一场战斗：哪些敌人、敌方支援、三星条件、掉落
  maps/
    main/           # 主线：纯手作
    season/         # 赛季远征：纯手作
    weekly/         # 周常：手作骨架 + 随机槽位
    daily/          # 日常：生成器模板 + 素材池
  stories/          # 剧情脚本（对白、选项、标记）
  rewards/          # 掉落表
  dungeons.json     # 资源副本
  packs.json        # 卡包概率
  quests.json       # 签到 / 日常 / 周常 / 月常
  progression.json  # 经验表、碎片值、经验道具、返还比例
  items.json        # 物品定义（碎片、经验道具、材料）
```

启动时整个目录过一遍 schema，引用不存在的 id（比如遭遇引用了一个没有的敌人）直接报错，拒绝启动。

## 3. 实体

> 3.1、3.2 是开工前的草案。敌人、敌方支援、遭遇已在第 3 步落地，实际格式（文件名即 id、招式表 + 脚本、`variants`、条件原语、支援类型）以 `战斗内容编写指南 v0.1.md` 为准。

### 3.1 敌人 `enemies/*.json`

```jsonc
{
  "id": "offbeat-conductor",
  "name": "失拍指挥·终曲",
  "tier": "boss",                 // normal / elite / boss
  "element": "dark",
  "weaknesses": ["light", "ice", "fire"],
  "stats": { "hp": 120000, "atk": 1080, "int": 1180, "def": 2800 },
  "actionsPerTurn": [3, 4],
  "ai": {
    "moves": {
      "ult":   { "kind": "heavy_magic", "element": "dark", "power": 2.2, "causesDown": true, "chargedUltimate": true },
      "beam":  { "kind": "magic", "element": "dark", "power": 0.95 },
      "storm": { "kind": "heavy_magic", "element": "fire", "power": 1.35, "status": "burn", "hardToInterrupt": true }
    },
    "script": [
      { "when": { "supportStacks": { "id": "charge", "gte": 2 } }, "use": "ult" },
      { "otherwise": "beam" },
      { "always": "storm" },
      { "when": { "turnMod": [2, 0] }, "use": "break-support" },
      { "otherwise": "add-support" }
    ]
  }
}
```

AI 只用引擎提供的**条件原语**（回合奇偶、血量阈值、支援层数、我方状态……）和**行为原语**（攻击、蓄力、拆支援、召唤……）组合。现在 `engine.ts` 里按敌人 id 写死的 `if` 分支，全部改成这种脚本。需要随机挑选时，由引擎从 `battle-N/enemy` 流里取。

### 3.2 遭遇 `encounters/*.json`

一场战斗 = 敌人 + 敌方支援 + 三星条件 + 掉落。同一个敌人可以出现在多个遭遇里。

```jsonc
{
  "id": "ch1-boss",
  "enemy": "offbeat-conductor",
  "supports": ["charge-gauge", "armor-1", "offbeat-minion"],
  "stars": [
    { "type": "turnsAtMost", "value": 6 },
    { "type": "noDown" },
    { "type": "apSpentAtMost", "value": 18 }
  ],
  "rewards": "drop-ch1-boss"
}
```

三星条件类型由引擎提供，可以随时新增：`turnsAtMost`、`noDown`、`apSpentAtMost`、`finishWithElement`、`noSupportUsed`、`maxHpLossPercent`……每关自己挑 3 个、自己填参数。

### 3.3 地图 `maps/*.json`

文件名就是地图 id（只用字母、数字和连字符）。

```jsonc
{
  "kind": "main",                 // main / season / weekly / daily
  "name": "第一章 · 起拍",
  "summary": "……",
  "staminaCost": 0,               // 主线和赛季必须是 0；日常、周常消耗体力
  "deckSize": 14,                 // 出征前要选满几张卡（卡池）
  "start": "n1",
  "rewards": "drop-ch1-clear",    // 通关整张图时发的掉落表
  "nodes": {
    "n1": { "type": "story", "story": "ch1-intro", "pos": [0, 0], "next": ["n2"] },
    "n2": { "type": "battle", "encounter": "ch1-ghost", "rewards": "drop-ch1-battle", "pos": [1, 0], "next": ["n3"] },
    "n3": { "type": "branch", "prompt": "前面有两条路", "pos": [2, 0], "next": ["n4a", "n4b"] },
    "n4a": { "type": "rest", "title": "篝火", "pos": [3, -1], "next": ["n5"] },
    "n4b": { "type": "treasure", "rewards": "drop-ch1-chest", "pos": [3, 1], "next": ["n5"],
             "requires": { "flag": "met-guide" } },
    "n5": { "type": "boss", "encounter": "ch1-boss", "rewards": "drop-ch1-boss", "pos": [4, 0], "next": [] }
  }
}
```

掉落表引用放在**地图节点**（和地图顶层的通关奖励）上，不放在遭遇上——这样同一个遭遇放到不同地图里可以给不同的掉落。

节点类型：

| 类型 | 作用 |
|---|---|
| `battle` / `boss` | 进入一场遭遇，可带节点掉落表 `rewards` |
| `story` | 播放剧情，可以设置标记 |
| `event` | 带选项的事件（格式已预留，运行时稍后接入） |
| `treasure` | 进入节点时由远征种子当场掷出掉落表 `rewards`，记入待结算奖励 |
| `rest` | 回复队伍 HP（回满） |
| `branch` | 只是分叉口，选择下一条路 |
| `slot` | 随机槽位，由 4B 的地图生成器在开始出征前替换成具体节点 |

分支不规定一难一易。`requires: { flag }` 用剧情设置过的标记锁路；如果一个节点后面的所有路都带 `requires`，校验会直接报错（避免没拿到标记时卡死）。`pos` 只给前端画格子用，服务端不关心。地图必须是单向无环图，所有节点从 `start` 可达，且至少有一个终点（`next` 为空）。

### 3.4 三种地图来源

| 类型 | 做法 |
|---|---|
| 主线、赛季远征 | 纯手作，JSON 里写死全部节点 |
| 周常 | 手作骨架，部分节点写成**槽位**：`{ "type": "slot", "pool": "patrol-mid" }`，并在 `pools` 里写出候选节点与权重；开始出征时由 `map-slots` 随机流从池里挑具体节点替换（保留原来的 `pos`、`next`、`requires`） |
| 日常 | 不手写 `nodes`，改写 `generate` 生成模板：总层数 `layers`（第 1 层单起点普通战、最后 1 层单终点 Boss）、中间层分叉率 `branchRate`、节点类型权重 `weights`（`battle` / `rest` / `treasure`）、普通遭遇池 `battles`、终点 Boss 池 `bosses`、宝箱掉落池 `chests`；开始出征时由 `map-gen` 随机流现场生成整张图 |

生成器是规则层的纯函数：`materializeMap(mapDef, seed) → MapDef`（位于 `packages/shared/src/expedition/generator.ts`）。同一个种子永远生成同一张图。日常地图的种子按 `daily:<玩家id>:<地图id>:<北京时间4:00日周期>` 固定（当天通关后再进则加 `#<今日已通次数>`），放弃重进不会换图。开始出征时服务端把展开后的成品 `MapDef` 和玩家选的卡池一起存成快照，途中内容更新或强化卡牌都不影响当次出征。

### 3.5 剧情 `stories/*.json`

文件名就是剧情 id。

```jsonc
{
  "title": "第一章 · 开场",
  "lines": [
    { "speaker": "向导", "text": "……" },
    { "choice": [
      { "text": "跟上去", "set": ["met-guide"] },
      { "text": "留在原地", "set": [] }
    ] }
  ]
}
```

剧情选项只能设置标记，不能直接发奖励；奖励只从节点和掉落表来，方便核对经济。

### 3.6 掉落表 `rewards/*.json`

文件名就是掉落表 id。每一份奖励的结构和邮件附件一致（`coins`、`essence`、`stamina`、`items`、`packs`、`cards`），外加 `playerExp`（玩家经验）。

```jsonc
{
  "fixed": { "coins": 200, "playerExp": 100, "items": [{ "itemId": "exp-medium", "count": 2 }] },
  "random": {
    "rolls": 2,
    "entries": [
      { "weight": 3, "reward": { "coins": 50 } },
      { "weight": 1 }
    ]
  },
  "starBonus": {
    "3": { "items": [{ "itemId": "shard-R", "count": 4 }] }
  },
  "firstClear": { "packs": [{ "pool": "golden", "count": 1 }] }
}
```

发放顺序：`fixed` → `random`（独立抽 `rolls` 次，按 `weight` 加权，不写 `reward` 表示空奖）→ `starBonus`（累加：3 星同时拿 `"1"`、`"2"`、`"3"` 三档）→ `firstClear`（只在地图级通关掉落表且首次通关该地图时发）。掉落全部由远征种子派生独立随机流（`loot-<节点id>`、`treasure-<节点id>`、`clear`）在服务端计算，累计到待发奖励里，出征结算时一次性入账并写流水。

### 3.7 任务与签到 `quests.json`（第 5 步已落地）

单文件，由 `packages/shared/src/quests.ts`（格式）和 `quest-content.ts`（引用校验）检查；`pnpm content:check` 会核对物品、卡包是否存在、id 是否合法、签到 id `sign-in` 没被占用。

```jsonc
{
  "signIn": {
    "base": { "coins": 50 },                       // 平时每天
    "bonus": { "7": { "coins": 100, "packs": [{ "pool": "normal", "count": 2 }] } }  // 本月第几天的特别奖励（键 1–31）
  },
  "quests": {
    "daily-open-pack": {
      "period": "daily",          // daily / weekly / monthly
      "name": "拆一包", "desc": "开 1 个卡包",
      "event": "pack-open",       // 服务端记账的事件，见下表
      "target": 1,
      "mapKind": "weekly",        // 可选，只能配在 expedition-* 事件上
      "rewards": { "coins": 40 }, // 和邮件附件同一套字段（不含卡牌）
      "points": 1                 // 活跃点，领奖时才算；目前只记账，通行证以后用
    }
  }
}
```

事件（`QUEST_EVENTS`）：`sign-in`、`pack-open`（每包 1 次）、`feed`（每次喂养 1 次）、`fuse`（每次融合 1 次）、`dismantle`（每张卡 1 次）、`dungeon-run`、`market-buy`、`market-sell`（成交才算，双方各一笔）、`expedition-win`（远征里打赢一场战斗）、`expedition-clear`（走到终点通关，「到此结算」不算）。新增事件要同时在服务端动作里加一行 `recordQuestEvent`。

**重置不靠定时任务。** 进度表 `quest_progress` 按「周期编号」存一行：日常 = 重置日（`2026-11-24`，每天 4:00 换）、周常 = 这周周一的重置日（周一 4:00 换）、月常 = `2026-11`（每月 1 日 4:00 换）。换了编号就是新的一行，自然从 0 开始。编号函数在 `packages/shared/src/reset.ts`。

**记账**在发生动作的同一个事务里做（`apps/api/src/quest-events.ts`）：动作回滚，进度一起回滚；进度封顶在目标数。

**领奖**（`apps/api/src/quests.ts`）：事务里先 `lockUser`，再检查「进度够、这一周期没领过」，走 `grantAttachment` 发奖，流水来源 `quest`（`sourceRef` = `任务id@周期编号`）。重复点、并发点只会发一次。一键全领是同一套逻辑，整批一个事务，任何一条出错整批回滚。

**签到**：每天 4:00 换日，一天一次，不补签；奖励按「本月第几天」查 `bonus`，没写的天用 `base`。签到记录也存在 `quest_progress`（`quest_id = sign-in`，`period_key` = 重置日），顺带给 `event: sign-in` 的任务记一笔；流水来源 `sign-in`。

**周期结束时没领的奖励**：下次读任务时顺便处理（和远征到期、邮件清理同一种「读时顺便做」）——已完成但没领的合成一封邮件发到邮箱（附件原样，玩家自己去领），未完成的作废并清掉进度行；内容里已经删掉的任务留下的行也一并清理。先在事务里把行抢成「已领取（`auto_claimed`）」再发信，并发读取只会发一封。

## 4. 出征的状态与结算

体力原则：**拿到东西才扣体力**。主线、赛季远征不消耗体力，靠关卡设计卡进度；日常、周常、资源副本消耗体力。

| 操作 | 服务端行为 |
|---|---|
| 开始 | 检查体力够不够，**冻结**这部分体力（不能同时开多场把体力用超），生成种子，写 `runs`（记录 `contentVersion`） |
| 每回合 | 追加操作到 `run_actions`，不复算 |
| 战斗结束 | 复算这一场，确认胜负和星级，锁定；奖励记到出征的「待结算」里 |
| 撤退结算 | 发放已锁定节点的待结算奖励；**有奖励才扣体力**，一个节点都没拿下则解冻退回 |
| 放弃 | 不发奖励，解冻退回体力 |
| 走完 | 发放全部奖励，扣体力，记录首通和路线 |

不扣体力就能放弃，会出现「不满意这张随机图就重来」的刷图。所以日常地图的种子按「玩家 + 地图 + 当天」固定，放弃后重新进入还是同一张图。冻结超时（例如 24 小时未结算）按撤退结算自动处理。

`contentVersion` 是 `content/` 的哈希。出征期间内容更新了，重放仍然用开始时的那一版。服务端保留最近几个版本的内容快照。
