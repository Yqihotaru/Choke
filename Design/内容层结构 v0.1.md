## 0. 已拍板的规则（2026-11-22，均已实现）

| 项 | 结论 |
|---|---|
| 融合 | 同名卡互吃，只提升命座 |
| 喂养 | 任意卡折算成经验喂给目标卡（基准 100%） |
| 分解 | 卡 → 若干个**同品质**碎片；碎片既是通用材料，也能当经验喂卡，约八折 |
| 经验道具 | 只从经验本掉；按体力折算要比喂卡更划算 |
| 已升级卡的返还 | 分解或被喂掉时，按投入经验的约 75% 返还**经验道具**（大/中/小拆分，尾数舍去） |
| 经验量级 | 所有经验数值整体 ×10（需求、卡、碎片、道具、副本同一次迁移），并切到 v0.3 §6.1 的表 |
| 强化界面 | 单独做：目标卡 + 卡/碎片/道具三栏多选 + 升级预览 |
| 种子 | 每次出征一个种子；各处按名字派生独立随机流（`map`、`battle-N/enemy`、`battle-N/player`），不存小种子 |
| 我方随机 | 暴击、伤害浮动、boost、必杀、连击、buff 随机选目标，全部走 `battle-N/player` |
| 提交 | 每回合把操作追加到服务端；刷新从服务端记录恢复；每场战斗结束由服务端复算并锁定；出征结束统一结算 |
| 战败 | 不能中途重开单场战斗；战败后三选一：到此结算、直接退出（不扣体力）、同种子重试（见《卡牌数值与战斗机制》§15） |
| 重置时间 | 北京时间 04:00（日常、签到）；周一 04:00（周常）；每月 1 日 04:00（月常） |

## 1. 三层

| 层 | 放在哪 | 内容 | 规则 |
|---|---|---|---|
| 规则 | `packages/shared` | 战斗引擎、伤害公式、AI 行为原语、条件求值、地图生成器 | 纯函数，无 IO，不 import 任何具体内容 |
| 内容 | `content/`（仓库根目录） | 敌人、遭遇、地图、剧情、掉落表、副本、卡包、任务 | 纯 JSON，由 `packages/shared` 里的 zod schema 校验 |
| 状态 | 数据库 | 玩家拥有什么、走到哪、领过什么 | 只存 id 引用内容，不存内容本身 |

引擎拿内容当参数：`createBattle(encounter, deck, rng)`，而不是 `if (presetId === "xxx")`。

## 2. 目录

```
content/
  enemies/            # 单个敌人：数值、属性、弱点、AI（一个文件一个，文件名即 id）
  encounters/         # 一场战斗：敌人、敌方支援、三星条件、简介
  maps/               # 地图，kind 字段区分主线 / 赛季 / 周常 / 日常
  events/             # 地图上的事件（带选项）
  stories/            # 剧情脚本（对白、选项、标记）
  rewards/            # 掉落表
  enemy-supports.json # 敌方支援，一个文件装全部
  shop.json           # 统一商店货架：日常补给、碎片博弈、限量保底（限购周期、售价、奖池）
  dungeons.json       # 资源副本
  packs.json          # 卡包概率
  quests.json         # 签到 / 日常 / 周常 / 月常 / 成就
  osu-daily.json      # 每日推荐谱面
  progression.json    # 卡与玩家经验表、碎片值、返还比例、突破金币与碎片、洗技能消耗、出征点数
  unlocks.json        # 功能解锁表：每个功能的等级、引导、账号条件
  items.json          # 物品定义（碎片、经验道具、材料）
  economy.json        # 镀闪精华、市场最高价等经济常量
```

- 目录下**只放 `.json`，不能再建子目录**：主线、赛季、周常、日常靠地图里的 `kind` 区分，不靠文件夹。
- 启动时整个目录过一遍 schema，引用不存在的 id（比如遭遇引用了一个没有的敌人）、目录里多出没接入的文件，都会直接报错，拒绝启动。
- 校验命令：`pnpm content:check`。内容版本号 `contentVersion` 是全部文件的哈希，每次出征开始时记一份。

## 3. 实体

> 敌人、敌方支援、遭遇的字段、招式、脚本条件和支援类型，全部以 `战斗内容编写指南 v0.1.md` 为准，本节只讲它们在内容层里的位置。

### 3.1 敌人 `enemies/*.json`

文件名即敌人 id。一个敌人 = 基础信息（名字、`tier`、属性、弱点、`stats`）+ AI（`moves` 招式表 + `script` 脚本）。节选自 `content/enemies/conductor.json`：

```jsonc
{
  "name": "失拍指挥·终曲",
  "tier": "boss",                 // normal / elite / boss
  "element": "dark",
  "weaknesses": ["light", "ice", "fire"],
  "stats": { "hp": 120000, "atk": 1080, "int": 1180, "def": 2800 },
  "ai": {
    "moves": {
      "ult":  { "kind": "heavy_magic", "label": "…", "element": "dark", "power": 2.2, "causesDown": true, "chargedUltimate": true, "desc": "…" },
      "beam": { "kind": "magic", "label": "…", "element": "dark", "power": 0.95, "desc": "…" }
    },
    "script": [
      { "when": { "supportStacks": { "support": "enemy-sup-conductor-charge", "gte": 2 } }, "use": "ult" },
      { "otherwise": "beam" }
    ]
  }
}
```

AI 只用引擎提供的**条件原语**（回合奇偶、血量阈值、支援层数……）和**行为原语**（攻击、蓄力、拆支援、召唤、回血……）组合，引擎里不再有按敌人 id 写死的分支。需要随机挑选时，由引擎从 `battle-N/enemy` 流里取。

### 3.2 遭遇 `encounters/*.json`

一场战斗 = 敌人 + 敌方支援 + 三星条件 + 简介。同一个敌人可以出现在多个遭遇里。**掉落不写在遭遇里**，写在地图节点上（见 3.3）。

```jsonc
{
  "enemy": "conductor",
  "supports": ["enemy-sup-conductor-charge", "enemy-sup-conductor-armor", "enemy-sup-conductor-minion"],
  "stars": [
    { "type": "turnsAtMost", "value": 6 },
    { "type": "noDown" },
    { "type": "apSpentAtMost", "value": 18 }
  ],
  "summary": "终曲 BOSS：……"
}
```

`stars` 必须正好 3 条、类型互不重复。现在只有三种类型：`turnsAtMost`、`noDown`、`apSpentAtMost`（判定在 `battle/stars.ts`）；要新增类型得改代码。

### 3.3 地图 `maps/*.json`

文件名就是地图 id（只用字母、数字和连字符）。

```jsonc
{
  "kind": "main",                 // main / season / weekly / daily
  "name": "第一章 · 起拍",
  "summary": "……",
  "staminaCost": 0,               // 主线和赛季必须是 0；日常、周常消耗体力
  "deckSize": 14,                 // 出征前要选满几张卡（卡池，含替补）；其中上场 4–7 张由出征点数决定
  "start": "n1",
  "rewards": "drop-ch1-clear",    // 通关整张图时发的掉落表
  "difficulty": { },              // 可选，不写用默认：威胁值阈值 3/6/10/15、血量倍率 ×1/1.3/1.7/2.2/3
  "objectives": [ ],              // 可选，最多 3 个通关目标：{ "tierAtLeast": N } 或 { "flag": "…" }，每个算 1 颗星
  "nodes": {
    "n1": { "type": "story", "story": "ch1-intro", "pos": [0, 0], "next": ["n2"] },
    "n2": { "type": "battle", "encounter": "ch1-ghost", "rewards": "drop-ch1-battle", "pos": [1, 0], "next": ["n3"] },
    "n3": { "type": "branch", "prompt": "前面有两条路", "pos": [2, 0], "next": ["n4a", "n4b"] },
    "n4a": { "type": "rest", "title": "篝火", "pos": [3, -1], "next": ["n5"] },
    "n4b": { "type": "treasure", "rewards": "drop-ch1-chest", "pos": [3, 1], "next": ["n5"],
             "requires": { "flag": "met-guide" }, "threat": 2 },
    "n5": { "type": "boss", "encounter": "ch1-boss", "rewards": "drop-ch1-boss", "pos": [4, 0], "next": [] }
  }
}
```

掉落表引用放在**地图节点**（和地图顶层的通关奖励）上，不放在遭遇上——这样同一个遭遇放到不同地图里可以给不同的掉落。节点上的 `threat`（-20 到 20）是走进这格时威胁值的加减，威胁值累计到阈值就升难度档位；普通战斗打赢不涨。

节点类型：

| 类型 | 作用 |
|---|---|
| `battle` / `boss` | 进入一场遭遇，可带节点掉落表 `rewards` |
| `story` | 播放剧情，可以设置标记 |
| `event` | 带选项的事件，`event` 字段引用 `events/*.json`（见 3.3.1），已接入运行时 |
| `treasure` | 进入节点时由远征种子当场掷出掉落表 `rewards`，记入待结算奖励 |
| `rest` | 回复队伍 HP（回满） |
| `branch` | 只是分叉口，选择下一条路 |
| `slot` | 随机槽位，由地图生成器在开始出征前替换成具体节点 |

分支不规定一难一易。`requires: { flag }` 用剧情设置过的标记锁路；如果一个节点后面的所有路都带 `requires`，校验会直接报错（避免没拿到标记时卡死）。`pos` 只给前端画格子用，服务端不关心。地图必须是单向无环图，所有节点从 `start` 可达，且至少有一个终点（`next` 为空）。

#### 3.3.1 事件 `events/*.json`

文件名即事件 id，由地图的 `event` 节点引用。一个事件有标题、正文和 2–4 个选项：

```jsonc
{
  "title": "古老的祭坛",
  "text": "路边立着一座布满裂纹的祭坛……",
  "options": [
    { "text": "献上鲜血，换取力量（前方变危险，但有赏钱）", "threat": 3, "reward": { "coins": 100 } },
    { "text": "安静祈祷（队伍损失一些体力，得到祝福）", "hpLossPct": 0.2, "set": ["blessed"] },
    { "text": "绕开离去" }
  ]
}
```

选项**只能做这 4 件事**（白名单，写别的字段会被拒绝）：`threat` 加减威胁值（-20 到 20）、`hpLossPct` 扣队伍最大生命的比例（最多 0.5，最多扣到剩 5%，不会直接打死）、`reward` 给奖励、`set` 设标记。

### 3.4 三种地图来源

| 类型 | 做法 |
|---|---|
| 主线、赛季远征 | 纯手作，JSON 里写死全部节点 |
| 周常 | 手作骨架，部分节点写成**槽位**：`{ "type": "slot", "pool": "patrol-mid" }`，并在 `pools` 里写出候选节点与权重；开始出征时由 `map-slots` 随机流从池里挑具体节点替换（保留原来的 `pos`、`next`、`requires`） |
| 日常 | 不手写 `nodes`，改写 `generate` 生成模板：总层数 `layers`（第 1 层单起点普通战、最后 1 层单终点 Boss）、中间层分叉率 `branchRate`、节点类型权重 `weights`（`battle` / `rest` / `treasure`）、普通遭遇池 `battles`、终点 Boss 池 `bosses`、宝箱掉落池 `chests`；开始出征时由 `map-gen` 随机流现场生成整张图 |

生成器是规则层的纯函数：`materializeMap(mapDef, seed) → MapDef`（位于 `packages/shared/src/expedition/generator.ts`）。同一个种子永远生成同一张图。日常地图的种子按 `daily:<玩家id>:<地图id>:<北京时间4:00日周期>` 固定（当天通关后再进则加 `#<今日已通次数>`），放弃重进不会换图。开始出征时服务端把展开后的成品 `MapDef` 和玩家选的卡池一起存成快照，途中内容更新或强化卡牌都不影响当次出征。

### 3.5 剧情 `stories/*.json`

文件名就是剧情 id。

```jsonc
{
  "title": "第一章 · 开场",
  "lines": [
    { "speaker": "向导", "text": "……" },
    { "choice": [
      { "text": "跟上去", "set": ["met-guide"] },
      { "text": "留在原地", "set": [] }
    ] }
  ]
}
```

剧情选项只能设置标记，不能直接发奖励；奖励只从节点和掉落表来，方便核对经济。

### 3.6 掉落表 `rewards/*.json`

文件名就是掉落表 id。每一份奖励的结构和邮件附件一致（`coins`、`essence`、`stamina`、`items`、`packs`、`cards`），外加 `playerExp`（玩家经验）。

```jsonc
{
  "fixed": { "coins": 200, "playerExp": 100, "items": [{ "itemId": "exp-medium", "count": 2 }] },
  "random": {
    "rolls": 2,
    "entries": [
      { "weight": 3, "reward": { "coins": 50 } },
      { "weight": 1 }
    ]
  },
  "starBonus": {
    "3": { "items": [{ "itemId": "shard-R", "count": 4 }] }
  },
  "firstClear": { "packs": [{ "pool": "golden", "count": 1 }] }
}
```

发放顺序：`fixed` → `random`（独立抽 `rolls` 次，按 `weight` 加权，不写 `reward` 表示空奖）→ `starBonus`（累加：3 星同时拿 `"1"`、`"2"`、`"3"` 三档）→ `firstClear`（只在地图级通关掉落表且首次通关该地图时发）。掉落全部由远征种子派生独立随机流（`loot-<节点id>`、`treasure-<节点id>`、`clear`）在服务端计算，累计到待发奖励里，出征结算时一次性入账并写流水。

### 3.7 任务与签到 `quests.json`（第 5 步已落地）

单文件，由 `packages/shared/src/quests.ts`（格式）和 `quest-content.ts`（引用校验）检查；`pnpm content:check` 会核对物品、卡包、地图是否存在、id 是否合法、签到 id `sign-in` 没被占用，以及下面几条规则。

```jsonc
{
  "signIn": {
    "base": { "coins": 50 },                       // 平时每天
    "bonus": { "7": { "coins": 100, "packs": [{ "pool": "normal", "count": 2 }] } }  // 本月第几天的特别奖励（键 1–31）
  },
  "activity": {                                    // 活跃度宝箱：每个周期一排，没写的周期没有宝箱
    "daily": [
      { "at": 20, "rewards": { "packs": [{ "pool": "normal", "count": 2 }] } },
      { "at": 100, "rewards": { "packs": [{ "pool": "golden", "count": 2 }] } }
    ]
  },
  "quests": {
    "daily-open-pack": {
      "period": "daily",          // daily / weekly / monthly / once（一次性成就）
      "group": "收集",            // 可选，成就页分栏小标题
      "name": "拆一包", "desc": "开 1 个卡包",
      "event": "pack-open",       // 服务端记账的事件，见下表
      "target": 1,
      "mapKind": "weekly",        // 可选，只能配在 expedition-* 事件上
      "mapId": "some-map",        // 可选，只记这张地图；只能配在 expedition-* 事件上，地图必须存在，mapKind 写了的话要一致
      "minRarity": "L",           // 可选，只记这个稀有度及以上的卡；只能配在 card-obtain 事件上
      "rewards": { "coins": 40 }, // 和邮件附件同一套字段（不含卡牌），外加 playerExp（玩家经验）
      "points": 10                // 活跃点，领奖时才算；once 必须是 0
    }
  }
}
```

**事件**（`QUEST_EVENTS`）：

- 累加类：`sign-in`、`pack-open`（每包 1 次）、`feed`（每次喂养 1 次）、`fuse`（每次融合 1 次）、`dismantle`（每张卡 1 次）、`dungeon-run`、`market-buy`、`market-sell`（成交才算，双方各一笔）、`osu-daily-pass`（通过当天的推荐谱面，见 3.8）、`expedition-win`（远征里打赢一场战斗）、`expedition-clear`（走到终点通关，「到此结算」不算）、`expedition-perfect`（通关且拿到地图的最高星级）、`card-obtain`（获得一张卡，可配 `minRarity`）。
- **取最大值类**（`QUEST_MAX_EVENTS`，进度不是累加，而是「到目前为止达到过的最高值」）：`expedition-tier`（通关时的难度档位 1–5）、`card-level`（卡等级）、`constellation`（命座）、`player-level`（玩家等级）。玩家等级升级的地方有好几处，所以不逐个埋点，而是读任务 / 领奖前把当前等级补记一笔。

新增事件要同时在服务端动作里加一行 `recordQuestEvent`。

**一次性成就**：`period: "once"`。进度行的周期编号恒为 `once`，永不换行、永不过期，也不会被转成邮件；领一次就结束。没有活跃点（`points` 必须是 0）。

**活跃度宝箱**：每个周期（日 / 周 / 月）各有一排宝箱，`at` 从小到大，最大一档就是活跃点上限（现在是 100）；校验会拒绝「最大一档比该周期任务点数总和还高」（永远领不到）。活跃点沿用「领任务时才算」：领一条任务，同一个事务里给当期活跃点加上 `points`（封顶），并为已经够点数的档位生成「待领」宝箱行。点数和宝箱都存在 `quest_progress` 里，用 `@` 开头的假任务 id（普通 id 的正则不允许 `@`，不会冲突）：`@points-daily`（点数计数）、`@chest-daily-40`（40 点宝箱，`claimed_at` 有值就是领过了）。因为宝箱也是进度行，周期结束没领的宝箱会自动走下面的「转邮件」。领宝箱的流水来源是 `quest-chest`。

**重置不靠定时任务。** 进度表 `quest_progress` 按「周期编号」存一行：日常 = 重置日（`2026-11-24`，每天 4:00 换）、周常 = 这周周一的重置日（周一 4:00 换）、月常 = `2026-11`（每月 1 日 4:00 换）。换了编号就是新的一行，自然从 0 开始。编号函数在 `packages/shared/src/reset.ts`。

**记账**在发生动作的同一个事务里做（`apps/api/src/quest-events.ts`）：动作回滚，进度一起回滚；进度封顶在目标数。

**领奖**（`apps/api/src/quests.ts`）：事务里先 `lockUser`，再检查「进度够、这一周期没领过」，走 `grantAttachment` 发奖，流水来源 `quest`（`sourceRef` = `任务id@周期编号`）。重复点、并发点只会发一次。一键全领是同一套逻辑，整批一个事务，任何一条出错整批回滚。

**玩家经验**：任务、宝箱、签到的奖励里可以写 `playerExp`。它不是邮件附件字段，领奖时不走 `grantAttachment`，而是同事务里用 `addPlayerExperience`（`apps/api/src/player-exp.ts`）直接加到账号上并处理升级，不写流水；领奖结果里会有一行 `kind: "playerExp"` 给界面显示。升级后的 `player-level` 成就在下次读任务时补记。

**签到**：每天 4:00 换日，一天一次，不补签；奖励按「本月第几天」查 `bonus`，没写的天用 `base`。签到记录也存在 `quest_progress`（`quest_id = sign-in`，`period_key` = 重置日），顺带给 `event: sign-in` 的任务记一笔；流水来源 `sign-in`。

**周期结束时没领的奖励**：下次读任务时顺便处理（和远征到期、邮件清理同一种「读时顺便做」）——已完成但没领的合成一封邮件发到邮箱（附件原样，玩家自己去领），未完成的作废并清掉进度行；其中的玩家经验在转邮件时直接加到账号上（不放进附件，邮件正文会提一句）；内容里已经删掉的任务留下的行也一并清理。先在事务里把行抢成「已领取（`auto_claimed`）」再发信，并发读取只会发一封。

### 3.8 每日推荐谱面 `osu-daily.json`

```json
{
  "pool": [
    { "beatmapId": 3449082, "title": "艺术家 - 曲名 [难度名]" },
    { "beatmapId": 2427416, "title": "…", "minAccuracy": 95, "minRank": "S" }
  ],
  "schedule": { "2026-11-25": 2427416 }
}
```

- `pool`：候选谱面。`minAccuracy`（1–100 的百分数）、`minRank`（`D` / `C` / `B` / `A` / `S` / `SS`）可选，写了才判断。**只认 osu! standard**，不分模式。
- `schedule`：可选，哪天想用哪张就写（键是重置日 `YYYY-MM-DD`，值必须是池子里的 `beatmapId`）。没写的天自动轮换，所以哪天懒得安排，当天会自己换一张顶上。
- 轮换（`osuDailyFor`）：把池子按「圈数」做种子洗牌，一圈用完之前不重复，相邻两圈的交界也不会连着同一张；不存数据库，同样内容同一天任何时候算出来都一样。**往池子里加减谱面会改变之后的排列**（今天和过去已经发生的不受影响，因为玩家的通过记录存的是成绩，不是排列）。
- 判定（`judgeScore`）：必须 Pass、结束时间在今天 4:00 到明天 4:00 之间；X / XH 算 SS，SH 算 S。
- 服务端（`apps/api/src/osu-daily.ts`）：用应用自己的 client credentials 令牌读公开成绩（`apps/api/src/osu-api.ts`，玩家不用重新授权）；每个玩家检查后冷却 60 秒；全服每分钟最多 40 次 osu! 请求（官方限频约 60）；同一条成绩只能用一次，存在 `osu_score_claims`（`score_id` 唯一，迁移 `0015`）。
- 奖励不在这个文件里：在 `quests.json` 里写一个 `event: "osu-daily-pass"` 的任务（样例 `daily-osu-beatmap`：2 个普通包、30 活跃点），周常、月常、成就也能用这个事件。

## 4. 出征的状态与结算

体力原则：**拿到东西才扣体力**。主线、赛季远征不消耗体力，靠关卡设计卡进度；日常、周常、资源副本消耗体力。

出征存在 `expeditions` 表，每场战斗存在 `expedition_battles` 表（含操作记录 `actions`）；通关星级和次数存在 `map_clears`，图鉴存在 `bestiary`。同一玩家同时只能有一个未结束的出征（数据库唯一索引保证）。

| 操作 | 服务端行为 |
|---|---|
| 开始 | 检查体力和出征点数，**冻结**这部分体力（不能同时开多场把体力用超），生成种子，存地图快照、卡池快照、点数分配和 `contentVersion`，有效期 24 小时 |
| 每回合 | 把玩家操作追加到该场战斗的 `actions`，服务端逐条校验 |
| 战斗结束 | 用同一份规则复算（`replayBattle`），确认胜负和星级并锁定；奖励记到出征的「待结算」里 |
| 战败 | 三选一：到此结算（发已累计的奖励）、直接退出（不扣体力）、同种子重试 |
| 撤退结算 | 发放已锁定节点的待结算奖励；**有奖励才扣体力**，一个节点都没拿下则解冻退回 |
| 放弃 | 不发奖励，解冻退回体力 |
| 走完 | 发放全部奖励，扣体力，记录首通和星级 |
| 过期 | 24 小时无操作，下次读取时按撤退结算自动处理，奖励以邮件发出 |

不扣体力就能放弃，会出现「不满意这张随机图就重来」的刷图。所以日常地图的种子按「玩家 + 地图 + 当天」固定，放弃后重新进入还是同一张图。

`contentVersion` 是 `content/` 的哈希，只是留档，用来排查问题。**真正保证出征期间内容更新不影响当次出征的，是开始时存下的地图快照、遭遇快照和卡池快照**，重放用的就是这些快照。
