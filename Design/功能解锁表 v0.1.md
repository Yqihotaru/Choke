# 功能解锁表 v0.1

> 状态：**草案，数值全是占位**。还没有改任何代码和内容；改动方案见第 6 节。
> 目标：新玩家第 1 天只看到开包、卡册、组队、战斗；前 3 天（约 Lv15）把主要功能陆续解锁完；Lv50 大约要三周多；Lv50–60 非常陡，当作长期目标。
> 经济数值（经验发多少、每天预算）最终由经济研究定，这里给的是目标曲线。

## 1. 原则

1. **解锁靠"做过"，不只靠等级**。每个新功能解锁时，配一条"第一次用它"的引导和一次性成就；做完这件事就发经验，把玩家推到下一个解锁点。这样等级只是进度的记号，引导才是主线。
2. **一次只多一两样**。每次解锁最多出现 1–2 个新入口，不要一口气把桌面铺满。
3. **服务端要校验**。前端的锁只是提示；绕过界面直接调接口也必须被拒绝（现在只有市场做到了）。
4. **玩家等级反映"体验了多少内容"**，不是肝度。所以重复刷的事（开包、市场买卖、重复扫荡）不发玩家经验。

## 2. 现状（代码里已有的）

- 前端写死了一份解锁表：`src/tutorial/unlocks.ts`。Lv1：账号、关于、开包、卡册；Lv2：卡组、战斗；Lv3：背包、图鉴、邀请函、发牌按钮、市场。后面五样要先完成新手教程。
- 新手教程现在的步骤：开包 → 卡册 → 卡组 → 战斗 → 毕业（`packages/shared/src/tutorial.ts`）。毕业时等级补到 Lv3（`tutorialGraduateLevel`）。
- **服务端只校验了市场**（要教程毕业，且等级 ≥ `marketUnlockLevel`）。
- 出征点数随等级发（`content/progression.json` 的 `pointsByLevel`）：Lv1 给 8 点，Lv3、5、10、15、20…50 各 +3，Lv50 一共 41 点。
- 副本现在要先首通绑定的资源远征才能扫荡（服务端校验，`first_clear_required`）。
- 玩家经验来源：教程 250、副本每体力 1 点、资源远征首通 200–600。**任务、成就、主线都不发玩家经验**。

## 3. 经验曲线（目标）

升下一级所需经验（现在是 100 / 150 / 250 / 400 / 600 / 900，之后每级 ×1.22，到 Lv15 单级就要约 5,400）：

| 区间 | 每级所需 | 区间合计 | 到达该等级的累计 |
|---|---|---|---:|
| Lv1→2、Lv2→3 | 100、150（教程，不动） | 250 | Lv3：250 |
| Lv3→15 | 200 起缓升到 550 | 4,500 | **Lv15：约 4,750** |
| Lv15→50 | 约 580，缓升 | 约 20,300 | **Lv50：约 25,050** |
| Lv50→60 | 2,500 起，每级 ×1.12 | 约 43,900 | Lv60：约 68,900 |

按每天的经验供给估算（第 1 / 2 / 3 天约 1,500 / 1,600 / 1,650，之后每天约 1,000）：

| 时间 | 大约等级 |

| 第 1 天末 | Lv7 |
| 第 2 天末 | Lv11 |
| 第 3 天末 | Lv15 |
| 第 6 天 | Lv20 |
| 第 12 天 | Lv30 |

## 5. 解锁表

"条件"一栏：**引导**指要先完成对应的新手引导步骤；**等级**指玩家等级。大约时间按第 3 节的曲线估。

| 功能 | 条件 | 参考等级 | 大约时间 | 服务端要校验 |
|---|---|---|---|---|
| 账号、关于、开包、卡册 | 开局 | Lv1 | 开始 | 不需要 |
| 卡组、练习战 | 引导（开包 → 卡册之后） | Lv2 | 前 10 分钟 | 战斗接口校验已有卡组 |
| 背包、图鉴、邀请函、发牌 | **完成新手引导** | Lv3 | 第 1 天 | 否（只是入口） |
| **市场** | **完成新手引导**（不再看等级；游客账号仍不能用） | Lv3 | 第 1 天 | 是（已有） |
| 每日任务与签到、新手补给 | 完成新手引导 | Lv3 | 第 1 天 | 是 |
| 喂养、分解 | 等级 | Lv4 | 第 1 天 | 是 |
| 主线远征（第一章） | 等级 | Lv5 | 第 1 天 | 是 |
| 融合（升命座） | 等级 | Lv6 | 第 1 天 | 是 |
| 副本（练习室、碎片矿脉、精华回廊） | 等级 + 首通对应资源远征 | Lv8 | 第 2 天 | 是（首通已有，等级待加） |
| 体力药水、NPC 回收 | 等级 | Lv9 | 第 2 天 | 是 |
| 每日推荐谱面（要 osu! 账号） | 等级 | Lv10 | 第 2 天 | 是 |
| 周常任务 | 等级 | Lv10 | 第 2 天 | 是 |
| 远征难度档位 | 等级 | Lv12 | 第 3 天 | 是 |
| 镀闪（闪卡精华） | 等级 | Lv14 | 第 3 天 | 是 |
| 出征点数节点 | 等级：Lv3、5、10、15、20、25…50 各 +3 点 | Lv3–50 | 贯穿 | 是（已有） |
| 月常任务 | 等级 | Lv20 | 第 6 天 | 是 |
| 赛季远征 | 赛季开放 + 等级 | Lv15 | 第 3 天 | 是 |

**后话（赛季开了或做了再排）**：通行证、个人主页、名片、战队、成就页的完整入口。

### 解锁时的提示

- 桌面上未解锁的物件继续显示锁定态，写"Lv.N 解锁"或"完成新手引导后解锁"（现有写法，保留）。
- 解锁的瞬间：弹一次提示（哪个功能、怎么用），并发一次"首次使用"成就的提示条；不强制走完。
- 第一次用某个新功能时，只做一次轻引导（高亮 + 一句话），不阻断操作。

## 6. 实现方案（还没做，等确认）

1. **解锁表移到 `content/unlocks.json`**：每个功能一行，写条件（等级、引导步骤、首通某关）。前端和服务端读同一份，改表只动一个文件。现在写死的 `src/tutorial/unlocks.ts` 改成读它。
2. **服务端加统一的校验函数**：在喂养、分解、融合、出征、副本、体力药水、谱面、任务这些接口入口检查"这个玩家是否已解锁"，没解锁返回统一的错误码（比如 `feature_locked`，带上所需等级）。
3. **改 `content/progression.json`**：按第 3 节重排前 50 级的经验表，Lv50 之后单独一段。
4. **给主线奖励、任务宝箱、首次成就加 `playerExp`**，按第 4 节的预算。
5. 完成后跑 `pnpm test`、`pnpm test:pg`，补一个测试：没解锁时调接口被拒。

涉及前端的只有第 1 点（改读表的方式）和解锁提示，会碰前端文件，要和 fable 对一下。

## 7. 还没定的事

- 市场是否真的只看"完成引导"：这意味着新号几分钟后就能交易，要不要加一条"首次开包满 N 张"或"绑定 osu!"作为附加条件，防小号。
- 新手引导要不要加长：现在只到"战斗"一步，没有教喂养、融合、出征。建议每个新功能解锁时配一段轻引导（第 5 节末尾）。
- 体力药水、挂机包、NPC 回收在界面里的入口还没定，等 fable 的手机端重构。
- Lv15 之后新功能很少，可能要给 Lv20–50 留一些"解锁感"（新章节、更高难度、新卡池），这依赖内容量，先不排。
