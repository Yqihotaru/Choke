# 卡牌定义

> 状态：与代码一致（2026-11-25 核对）。代码位置：`packages/shared/src/card-def.ts`、`apps/api/src/db/schema.ts` 的 `cards` 与 `user_cards`。
> 卡池怎么来、稀有度怎么定见《卡池与稀有度规则 v0.1》；技能怎么发见《技能定义指南 v0.1》。

## 分三层

| 层 | 内容 | 存在哪 | 变不变 |
|---|---|---|---|
| **CardDef**（卡定义） | 身份、稀有度、职业、编号、玩家资料（国家、排名、pp、头像） | `cards` 表 | 静态，可热更（`version`） |
| **实例**（玩家手里的这一张） | 等级、经验、命座、闪卡、序号、个体值、**技能**、MOD | `user_cards` 表 | 每张卡各不相同 |
| **合成结果** `CardFaceData` | 以上合起来，给卡面和战斗用 | 运行时 | 不落库 |

**技能不在卡定义里，挂在实例上**：每张卡发出时掷一次，同名卡也各不相同，之后固定。卡定义里没有 `skills` 字段，实例只存技能 id。

运行时用 `faceFromDef(def, state)` 把卡定义 + 实例状态合成 `CardFaceData`，卡面组件只吃合成后的结果。技能的名字、费用、属性由 `cardSkillsFromRefs` 从技能表取，所以卡面印的和战斗里的永远一致。

## CardDef

```ts
interface CardDef {
  id: string                 // pool-{osuId} / hero-{osuId} / mirror-{osuId}
  osuId: number | null       // 对应的 osu! 玩家 id
  name: string
  rarity: Rarity             // C / UC / R / E / L / Mythic / Prismatic
  job: Job                   // tank / warrior / mage / support
  no: number                 // 卡面编号
  total: number              // 编号分母
  country?: string
  globalRank?: number | null
  pp?: number | null
  profileUrl?: string
  art?: string               // 头像地址，浏览器随看随载
  banner?: string            // 主页封面地址
  version: number            // 定义版本，只在定义字段变化时加一
}
```

三种来源（`cards.card_type`）：

| 类型 | id 前缀 | 说明 |
|---|---|---|
| `pool` | `pool-` | 公共卡池里的卡，卡包只抽这一种 |
| `hero` | `hero-` | 本体卡：玩家自己的卡，账号专属 |
| `mirror` | `mirror-` | 镜像卡：别的活跃玩家的镜像，账号专属，`origin_osu_id` 记来源 |

本体卡和镜像卡**不进公共卡池、图鉴统计和全服收集率**。`cards.hero_bonus` 与 `users.hero_bonus` 是废弃的死列（旧版个人加成，恒为 0，没实现）。

## 实例状态（`user_cards`）

| 字段 | 说明 |
|---|---|
| `level`、`exp` | 等级与当前等级内累计经验 |
| `constellation` | 命座。融合同名卡才涨 |
| `foil` | 闪卡，实例属性，任何卡都可能出 |
| `serial` | 这张卡的第几张：发行时从 `cards.pulled` 领号，分解、转手都不变 |
| `roll_bp` | 个体值，千分比 970–1030，抽到时掷一次，之后不变 |
| `skill_refs` | 这张卡的技能 id，见上 |
| `mods` | MOD 装槽（最多 3 个）。**列已有，MOD 系统还没做**，见《经济与养成系统 v0.3》§9 |

等级与命座上限在 `content/progression.json` 的 `card`：

| | 等级上限 | 命座上限 |
|---|---:|---:|
| 普通卡（含镜像卡） | 80 | 6 |
| 本体卡 | 12 | 8 |

## 导出与导入

- `/pool-lab`（前端试验页）按稀有度公式分池，导出 `choke-cards.json`，每张卡一行 `CardDefRow`（就是 `CardDef` 去掉 `version`，批量时统一）。
- `apps/api/scripts/import-cards.ts` 把它导入 `cards` 表：**整表替换卡定义**，先停 API。
- 单卡调试用 `/card-editor`，`defFromFace` 能把编辑器里的卡面转成 `CardDef`。

## 版本

- `version` 只在定义字段变化时加一；热更按 `id` upsert。
- **没有**"实例表存 `card_version`、按版本取定义"这回事：实例永远读最新定义。需要时再做，现在卡定义改动只有整表重导。
