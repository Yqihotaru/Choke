# Choke! 战斗结算与宝箱翻牌系统评估 v0.1

> 状态：暂缓上线（待经济风控与服务端校验闭环后启用）。
> 关联文档：`卡牌数值与战斗机制 v0.1.md` §12.3、`经济与养成系统 v0.3.md` §1.2–§3.2。

---

## 1. 背景与起源

在兰斯10原版战斗中，当敌方 BOSS 血量归零后，当前回合尚未结束，玩家可以继续消耗剩余 AP 对空血 BOSS 进行追击，触发 **OVER KILL（鞭尸加成 %）**。战斗结束进入 `WIN` 画面时：
1. **OVER KILL %** 直接转化为 **宝箱掉落概率加成** 与 **额外 EXP 加成**。
2. 画面左侧出现 **宝箱槽位**，点击翻开获得当场战利品（卡牌 / 材料 / 装备）。

---

## 2. 为什么当前版本暂缓上线宝箱翻牌

### 2.1 经济通胀与套利风险（核心原因）
根据 `经济与养成系统 v0.3.md` 的三条铁律与低通胀模型：
- **副本金币已清零**，日常材料与经验严格按体力配额（240 基础 + 120 药水）投放。
- 若在无体力限制或纯前端结算的练习/主线战斗中开放「OVER KILL 提升宝箱掉率 / 翻出卡包或金币」，会直接绕过体力阀门，形成 **无限重开刷满 OVER KILL → 刷材料/卡包** 的水龙头。
- 特别是平刀队 / 大招队在低难度关卡可以轻松打出 200%+ OVER KILL，如果直接挂钩高价值掉落，会击穿 v0.3 设定的月产 39 张 L、1.2 倍经验供需比。

### 2.2 前后端权威性边界
- 当前阶段 PvE 战斗在前端运行（`src/battle/engine.ts`），服务端尚未接入 `POST /battle/start`（下发随机种子）与 `POST /battle/submit`（回放复算校验）。
- 宝箱产出属于真实资产变更（写 `user_cards` / `user_packs` / 材料表），**绝不能由前端直接决定掉落并请求入库**，必须等 `packages/shared` 回放校验 + 服务端 RNG 闭环后，由服务端在校验通过时生成宝箱内容。

### 2.3 与三星评价（★1–★3）的职责重叠
`卡牌数值与战斗机制 v0.1.md §12.3` 已经定义了关卡评价体系：
- **通关**：打赢即过，不卡回合数。
- **★1 速通**：回合数 ≤ 基准值的 60%（利好爆发 / 平刀队）。
- **★2 无伤**：全程无人被 down（利好控场 / 坦克队）。
- **★3 高效**：全程 AP 消耗 ≤ 基准值的 80%（利好精算 build）。

如果同时存在「★3 省 AP」与「OVER KILL 倾泻剩余 AP 鞭尸」，两者在最后一回合的操作动机是**完全相反**的（省下 AP 拿 ★3 vs 花光 AP 刷 OVER KILL）。

---

## 3. 现阶段替代方案（已实装）

1. **战后结算采用 `战斗机制 v0.1` 的 ★1–★3 星级评价 + 玩家 EXP 结算**：
   - 清晰展示本场回合数、Down 次数、累计消耗 AP、最高 Combo 与三颗星的达成状态。
   - 宝箱翻牌 UI 从生产结算层移除，避免给玩家“翻了宝箱却没进背包”的虚假反馈。
2. **保留击破演出，不挂钩额外掉落**：
   - 击败敌人时保留爽快的终结演出与战果统计，待 M2/M3 服务端战斗回放校验与副本掉落表（`SH-11`）上线后，再将宝箱作为「体力副本 / 首通奖励展示容器」重新接入。

## 4. 后续重启宝箱系统的前置条件（Checklist）

- [ ] `POST /battle/start` 与 `POST /battle/submit` 落地，服务端完成确定性回放复算。
- [ ] 明确解决「★3 高效（省 AP）」与「OVER KILL（泄 AP）」的规则冲突（例如：进入 OVER KILL 阶段后的追击 AP 不计入 ★3 消耗统计，或仅在周本/模组本启用 OVER KILL 掉率加成）。
- [ ] 宝箱掉落严格绑定体力扣除事务（未扣体力或重打已领奖主线只给评价，不产宝箱）。
